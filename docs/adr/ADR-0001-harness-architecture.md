# ADR-0001：超级智能体 v0.1 的六条架构决策

- 状态：**Accepted（2026-11-07 用户按建议推进；D4 同日调整为本地隔离）**
- 日期：2026-11-05 ｜ 决策人：Lead ｜ 依据：`.ome/research/00-synthesis.md`（D1–D6）
- 背景：项目从 0 开始，P0 调研确认 2026 生产形态、成本结构与失败模式；以下六条一旦定下，后期改动成本高。

## D1 执行形态：单 agent 循环 + 受控 subagent
- 决策：v0.1 只做单 agent 循环；允许派生 subagent，但只回摘要、不共享上下文、不并行写文件。
- 备选：a) 自由多智能体（AutoGen/Crew 式）；b) 显式任务图（LangGraph 节点/边）。
- 理由：多智能体 ≈15× chat token（F-10）；MAST 实测 7 个开源 MAS 失败率 41%–86.7%，失败集中在系统设计与协作（F-07）；Anthropic 自家 agent teams 仍 experimental 默认关闭。
- 代价：超长任务只能靠压缩与文件外置，不能靠并行提速。
- 重议条件：单 agent 在 held-out 上触顶（完成率 <30%）且任务可切成独立并行子任务。

## D2 状态模型：append-only 事件日志 + 视图分离
- 决策：任务状态外置为事件日志（Event schema v1，见 SPEC §4）；compaction 只生成视图，不删事件。
- 备选：a) 直接存消息历史；b) 框架内置 checkpointer（LangGraph）。
- 理由：Managed Agents 的 session 就是 harness 外事件日志，崩溃可 wake 重放（F-04）；compaction 不可逆，不能作为唯一存储。
- 代价：要自己写事件 schema、回放与迁移；存储量增加。
- 重议条件：出现成熟中立标准（跨框架事件格式）。

## D3 工具协议：对外 MCP 2026-07-28，对内 execute() 适配
- 决策：工具统一走 `execute(name,input)=>string`；MCP server 作为适配器接入；工具定义默认不全量注入，按需发现（Tool Search 思路）。
- 备选：a) 纯自研 function calling；b) 直接用某框架的工具抽象。
- 理由：MCP 是事实标准（5.3 万 server 量级），2026-07-28 已无状态化（F-05）；全量注入 50+ 工具约 72K tokens（F-06）。
- 代价：适配层要维护；MCP 生态安全水位低（30%–82% 实现有缺陷），需白名单与审批。
- 重议条件：MCP 出现破坏性大版本，或工具生态转向 A2A。

## D4 执行环境：云沙箱 + 文件/网络双隔离 + 凭证不入沙箱
- 决策：代码执行默认云沙箱；网络默认拒绝、白名单放行；模型/云凭证不进入沙箱，由宿主代理注入。
- 2026-11-07 调整（用户确认）：**首版本地隔离**，用 OS 级文件/网络限制（如 Anthropic sandbox-runtime 同类方案）把执行限制在工作区与白名单内，云沙箱后置到上线前再评估；不接受无隔离的本地直跑。理由：首版先跑通、零外部成本；代价是本地隔离对定向攻击的强度低于云沙箱，发布前必须重新做威胁评估。
- 备选：a) 本地进程直跑；b) 自建 Firecracker/gVisor。
- 理由：自建隔离不划算且运维风险高；Codex 2026-08 已有真实逃逸个案；Anthropic 结论是文件与网络隔离必须同时。
- 代价：本地隔离有性能开销；云沙箱阶段有冷启动开销；离线场景受限。
- 重议条件：本地隔离的逃逸风险不可接受，或云沙箱成本显著下降。

## D5 交付面：文件工作区 + artifact + 轨迹回放
- 决策：产物落文件系统（版本/预览/校验和），event 至 artifact 有 provenance；轨迹可按序回放。
- 备选：a) 只返回聊天文本；b) 只存云文档。
- 理由：“交付成品”是超级智能体与聊天机器人的分界；轨迹是评测与调试的唯一数据来源。
- 代价：要设计 artifact 生命周期与清理策略。
- 重议条件：无（这是产品定义的一部分）。

## D6 验收判据：五项指标 + 20–30 条金标准 + pass^3
- 决策：任务成功率、pass^3、人工接管率、P95 时长（按时长分档）作为发布门槛；不计量费用；公开榜只用于对外沟通。
- 备选：a) 只看公开 benchmark；b) 只用人工感觉。
- 理由：公开榜饱和/不可比（GAIA 头部追平人类 92%，SWE-bench Pro 仅 23.3%，OSWorld 2.0 仅 20.6%，>163 分钟全 0）（F-09）。
- 代价：评测集要维护，pass^3 使评测耗时×3。
- 重议条件：拿到真实用户流量后，逐步以灰度指标替代人工判据。
