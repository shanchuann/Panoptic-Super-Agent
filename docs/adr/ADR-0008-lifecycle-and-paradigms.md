# ADR-0008：阶段化生命周期与任务范式路由

- 状态：**Accepted**（用户 2026-11-07 要求：增加项目问询阶段、任务阶段、交付阶段；迭代时复用已有内容快速重启；不同任务用不同开发方式）
- 决策人：用户 ｜ 记录：Lead ｜ 依据：[lifecycle.md](../../.ome/design/lifecycle.md)、[task-paradigms.md](../../.ome/design/task-paradigms.md)、[projects.md](../../.ome/design/projects.md)、oh-my-software-engineering 技能
- 关联：ADR-0006（协作拓扑）、ADR-0007（可演进性）、ADR-0009（事件驱动运行时）

## 背景

原设计只有一个执行阶段：用户提出目标后直接拆任务、跑任务，问询深度不足，spec 容易偏离创意；交付与维护也没有独立阶段。用户要求补上"问询 至 任务 至 交付 至 迭代"的阶段性交互，并明确"不同任务用不同开发方式"的范式路由。

## 决策

### L1 四阶段生命周期

~~~text
问询（Discovery/Spec） 至 任务（Build） 至 交付（Deliver/Maintain） 至 迭代（Iterate）
~~~

- 问询：澄清目标/非目标/成功判据/约束/参考；产出 Brief、Spec、排除清单、验收判据、计划摘要；一次确认；
- 任务：主交互阶段；图谱/看板/收件箱；支持删除/改进/插入/改派/接管；
- 交付：验收、交付五件套（代码/文档/截图/部署/版本号同一次构建）、维护计划、回滚点、冷启动测试；
- 迭代：继承 Brief/Spec/记忆/产物/任务基线，只跑差异任务与受影响下游。

阶段与项目状态映射：问询=draft/intake/planning；任务=active；交付=verifying/delivered；迭代=iterating。

### L2 任务范式注册表

- 维度分离：**任务类型决定 playbook（怎么做）**，规模与证据决定拓扑（谁做、并行多少）；
- P1 预置六类：research / code / doc / data / design / ops，各有默认步骤、工具白名单、技能集、验收器、默认拓扑；
- 路由：规则优先，置信度低时小模型分类；每次记录 type/playbook/mode/rationale；
- 混合任务拆分为类型化子任务，由 Lead 归并；
- 新类型 = 注册 playbook + 验证器 + 技能集，不改内核（ADR-0007）。

### L3 技能预设可插拔

- 文本、表格/数据、图像、前端、后端、代码管理六类技能包；
- 按项目/任务类型启用；可安装/卸载/禁用；卸载不影响内核；版本随项目锁定（可复现）。

### L4 任务阶段的变更控制

- 删除/改进/插入任务必须写事件并做影响评估（下游依赖、关键路径、时长、是否需重新确认）；
- 不允许静默修改验收判据；
- 用户接管自由，但接管行为写审计。

### L5 迭代的继承与加速

- 继承：Brief、Spec、L4 画像/决策/约束、产物基线、任务图；
- 差异：只确认"这次改什么/不改什么"；
- 执行：已完成任务不重跑，只跑差异与受影响下游；
- 指标：继承率 ≥60%、回归通过、旧版本保留。

## 备选与不选

| 备选 | 不选理由 |
|---|---|
| 保持单一执行阶段 | 问询不足导致返工在最贵处；交付与维护无门禁 |
| 问询阶段无限深挖 | 用户会被问卷淹没；改为"最多 3 问/轮 + 可跳过 + 快速/深挖模式" |
| 任务类型即拓扑 | 同一类型任务规模差异大；范式与拓扑必须正交 |
| 技能写死进代码 | 无法按项目替换/删除；与 ADR-0007 冲突 |
| 迭代从零开始 | 丢失已有资产；改为继承 + 差异执行 |

## 后果与风险

- 收益：不确定性前置；spec 更接近创意；交付有门禁；迭代更快。
- 代价：多一个问询阶段的交互成本；范式维护成本；技能包版本管理。
- 风险：问询过长（缓解：3 问上限 + 快速模式）；范式误判（缓解：规则优先 + 人工覆盖 + 审计）；技能包质量参差（缓解：版本锁定 + 评测）。
