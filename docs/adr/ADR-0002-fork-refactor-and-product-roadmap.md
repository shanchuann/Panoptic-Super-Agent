# ADR-0002：二次开发方式、重构边界与产品路线

- 状态：**Accepted（用户 2026-11-05 口述决策）**
- 决策人：用户 ｜ 记录：Lead ｜ 依据：用户架构输入 + `.ome/BROWNFIELD-BASELINE.md`
- 关联：ADR-0001（D1–D6，多数已由 DSH 基座满足）

## 背景
基座是 MIT 许可的 DeepSeek Harness（v0.2.1-rc.3，开发者预览）。用户明确：**在原有功能与界面基础上重构内容**，产品名万象超级智能体 / Panoptic Super；先 Web 验证，再做 win/mac/Linux 桌面端，后期移动端 App 远程控制桌面；**不跟进上游**；UI 尽量沿用官方设计、遵循开源协议。

## 决策

### A. 二次开发方式：Fork + 内容层重构（保留 UI 与功能外壳）
- 克隆基座为项目仓库，保留 git 历史与 MIT 版权声明；新增本项目版权行与 NOTICE。
- **保留**：Web/Desktop 应用壳与客户端 UI 组件、agent-loop、session 事件日志、tools 注册表、MCP 客户端、sandbox、deliverables、插件体系。
- **重构（用户点名）**：
  1. **记忆存储方式**：从“会话日志 + 压缩”扩展为“长期记忆子系统”（写入/检索/遗忘/可删除，可替换后端）；
  2. **模型调用方式**：统一模型网关 + 路由与降级 + 多模态配置（文本/图像/语音入口一致）；
  3. **会话管理**：会话生命周期、目标（goal）驱动的连续工作、多会话/多产物管理；**不动** JSONL 持久化格式与迁移链（避免破坏已发布数据）。
- 备选与不选理由：
  - 纯外挂插件（不改核心）：无法满足“记忆/模型/会话”三处重构，且用户要改的正是内容层 至 不选；
  - 纯 fork 全面重写：成本过高、丢掉基座成熟能力 至 不选。
- 代价：与上游分叉后，安全修复需自行评估 cherry-pick；基座破坏性变更无人兜底。

### B. 产品路线：Web 至 桌面（win/mac/Linux）至 移动端远程控制
| 阶段 | 范围 | 验收（草案） |
|---|---|---|
| P1 Web | 界面与基本功能确认：会话、任务、工具、插件、交付物 | 本机 `dsh web` 可跑；核心链路可演示；品牌替换完成 |
| P2 桌面 | Electron 客户端三平台打包（沿用基座 desktop 壳） | 三平台安装包可启；与 Web 共用数据 |
| P3 移动端 | App 远程控制桌面客户端（不把完整 agent 跑在手机） | 配对/鉴权/断线重连；操作可审计 |
移动端远程控制属高风险面（远程执行），单独立 ADR，不在 P1/P2 实现。

### C. 品牌与许可
- UI 设计**尽量沿用官方**（MIT 允许）；但所有可见品牌标识替换为 Panoptic Super / 万象超级智能体，不暗示 DeepSeek 官方背书（遵守其 `BRAND_GUIDELINES.zh.md`）。
- 本项目 LICENSE 沿用 **MIT**，保留原版权声明并追加本项目版权；第三方依赖通告沿用 `THIRD_PARTY_NOTICES.md`。

### D. 上游同步：不跟进
- fork 后自行维护；保留上游 commit 历史以便追溯。
- 例外：出现**高危安全漏洞**时，人工评估是否 cherry-pick（不改变“不跟进”的总策略）。

## “超”能力 至 DSH 扩展点映射（P1 落点）
| 能力（用户定义） | DSH 落点 | 备注 |
|---|---|---|
| 模型自行掌管对话 | `core/agent-loop` hook + `goal/*` + `plan/*` + 新增 autopilot 插件 | 必须挂资源限制与停止条件，否则失控 |
| 持续迭代交付升级 | `deliverables/*` + `goal-round-driver` + `schedule/*` | 交付版本化、可回滚 |
| 插件 | `boot/plugin-manager`、`boot/plugin-market`、`ctx.tools` | 基座原生，直接用 |
| 长时记忆 | 新增 memory 插件 + `storage/*` + session projection | 本次重构重点 |
| 多模态配置 | `llm/*` 适配器 + `attachment/*` + 设置页 | 统一入口，按能力路由 |
| 长时序规划 | `plan/*`、`goal/*`、`todo` | 与“自动掌管”共用停止/资源限制机制 |
| 跨领域工具面 | `ctx.tools` + `mcp/mcp-client` + `skill/*` | 不区分 Coding/Chat/Work，靠 preset 组合 |

## 后果与风险
- R1 分叉维护成本：安全补丁、依赖升级、Node/pnpm 升级全部自理；
- R2 三处重构耦合深：记忆/模型/会话互相引用，**必须先建基线再动**（B-001..B-004）；
- R3 远程控制面：P3 才做，但 P1 就要预留鉴权/审计接口，避免后期推倒；
- R4 品牌替换遗漏：官方 UI 内多处品牌文案/图标（`client/ui-brand-official` 等），需逐项清点。

## 重议条件
- 上游出现必须跟随的安全修复（可临时例外）；
- P1 发现三处重构超出“内容层”范围、需改 agent-loop 语义；
- 移动端远程控制的安全评估不通过。
