- 关联：ADR-0003（项目域）、ADR-0004（模型网关）、ADR-0005（记忆）

## 背景

单 Lead 分派模式让 Lead 同时承担上下文中枢、串行路由与决策三件事：项目一大就出现上下文膨胀、串行排队、单点判断。用户要求协作方式进化，同时保持"用户只有一个窗口"。

2026 一线证据：行业收敛到"协调者 + 单次交接"（Claude/Manus/Gemini/Deep Agents 同构）；多 Agent 的收益主要来自**上下文隔离**，失败主要来自**隐式决策不共享**（Anthropic 90.2% vs Cognition 反对）；黑板架构在 LLM 多 Agent 上已有实证（arXiv 2507.01701：与静态/动态 MAS 竞争且 token 更少）；长任务瓶颈是**状态保持**而非推理（LHTB：最强模型 46 题仅解 13）。

## 决策

### D1 三层上下文分离（复核补充）

- **对话面**：用户窗口只装目标、决策、结果、待办；协作状态不进入对话上下文；
- **协作面**：项目域（任务 DAG、产物、证据、审批、事件）是协作状态的唯一权威；必须是**可重建的事件 + 投影**，不是摘要；新增"决策 / 假设 / 禁止事项"一等记录；
- **执行面**：每个 Worker/Run 使用独立上下文包，不继承历史。

### D2 黑板优先，Lead 降级为仲裁者（拆分）

- 黑板（项目域）保留为协作状态权威；
- **路由由规则调度器执行，Lead 保留调度所有权、取舍与仲裁**；
- 任务领取/租约**推迟到 P2**，且仅用于均匀扇出批次；P1 由调度器按能力/写域分配。

### D3 协调策略层（缩小决策面）

- 决策对象收敛为三元组：**并行度 / 隔离级别 / 是否需人工闸门**，外加 mode 标签与理由；
- P1 只上规则；边界带小模型在累计 ≥200 条人工标注后才启用；
- 决策附带触发它的指标采样引用（上下文占用、失败次数、独立子任务数等）；
- 决策写入项目域审计，UI 节点详情可查看"为什么选这个模式"；用户可项目级强制模式。

### D4 最小充分范式 + 按证据升级（补适配条件）

- 升级前先尝试更便宜的路径：压缩、子任务隔离、拆句柄；
- 升级判据增加"**未言明决策数**"（子任务间共享假设超过阈值才禁止并行）；"上下文占用 >70%"是必要非充分条件；
- 迟滞：同一信号持续或超阈值才切换；只在项目启动、里程碑、阻塞事件重评估；
- 切换前必须 checkpoint + 生成上下文包；禁止运行中频繁切换。

### D5 模式菜单（收敛）

| 模式 | 说明 |
|---|---|
| M0 solo | 单 Agent 直接执行 |
| M1 orchestrator | 规则调度 + 单次交接（含扇出，默认） |
| M2 黑板状态模型 + 均匀扇出 | 项目域状态模型 + 并行批次调度（不采用领取式黑板作为默认） |
| M3 pipeline | 固定阶段链 |
| M4 两级扇出 | 最多两级，不设子 Lead 层级 |
| M5 辩论 | **移出运行时菜单**，仅作离线复核/人工工具 |
| M6 human | 升级给人 |

### D6 上下文包 / Context Broker（补字段与例外）

- 包内必含：任务目标、验收判据、相关产物、记忆卡、最近事件，以及 **decisions / assumptions / forbidden / upstreamDiffRef**；
- 提供**受控 fork 白名单**：强耦合子任务允许继承决策与约束，不允许继承完整轨迹；
- 验收指标：**交接信息丢失率**（判据/证据/产物齐全度）。

### D7 可解释与可审计（加回链）

- 每次决策记录 decisionId，可回链 runId、trace 与评测结果；
- 否则无法回答"失败是模型、工具还是编排"；
- 模式与实际执行不一致视为缺陷（调度器只认决策对象）。

### D8 黑板视图是只读投影（补三条）

- 项目域是唯一权威；看板/图谱/时间线/列表是只读投影，共享同一数据源；
- 用户的暂停、取消、重跑、审批、追问通过命令入口（卡片上直接提供），命令幂等、记录 actor、写审计；
- **跨执行单元的审批不可代答**；投影需标注过期/降级状态，避免 UI 显示陈旧状态；
- 不提供直接编辑状态的入口。

### D9 拓扑升级门槛（新增）

- 任何 M2 及以上拓扑，必须先有**自家 pass^k A/B 证据**才能进入默认路径；
- 无证据时保持 M0/M1；实验记录写入项目域审计（任务集、对照、结果）。

### D10 Run 身份与能力声明（新增）

- 每个 Run 携带可撤销身份与能力声明：角色、工具白名单、来源（谁派的）、审批人；审计只认该身份；
- 本地单机版用本地角色 id 实现，不引入企业 IdP；为将来 A2A 留位。

## 备选与不选

| 备选 | 不选理由 |
|---|---|
| 全模型判断拓扑 | 无产品/论文证据支持"评分选拓扑"；规则可覆盖多数情况 |
| 固定黑板/固定编排 | 小任务过度协调、大任务不够用 |
| 领取式黑板作为默认 | 无产品默认证据；P2 仅用于均匀扇出批次 |
| 自由多 Agent / 运行时辩论 | 约 15× 用量、协调失败率高、辩论有"由对转错"实证 |
| 竞价/合同网 | 本地单用户没有市场，只有开销（Magentic Marketplace：首提案偏差 10–30×） |
| 通用 Agent OS 内核 | 学术原型无生产验证；DSH 已有 loop/tool/session seam |

## 后果与风险

- 收益：项目变大时不被 Lead 上下文卡住；协作可并行、可解释；小任务保持简单。
- 代价：新增协调策略层与审计；台账与上下文包需要维护；模式与调度器需要契约测试。
- 风险：误判模式（缓解：D9 门槛 + 误升级率指标 + 人工覆盖）；拓扑抖动（迟滞）；选择器成为新瓶颈（规则化、毫秒级）；黑板数据膨胀（归档/删除）；台账腐烂（每日对账）。

## 重议条件

- 实测路由准确率 <60% 或误升级率 >20%，退回固定编排；
- M2/M4 的 pass^k 相对 M1 无显著提升，保持 M0/M1 默认；
- 上下文包组装开销超过任务时长 5%；
- 出现更强的标准化协作协议（如 A2A）可直接复用。
