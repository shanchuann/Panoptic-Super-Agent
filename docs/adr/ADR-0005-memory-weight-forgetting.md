# ADR-0005：记忆权重与遗忘策略

- 状态：**Accepted**（用户 2026-11-07 确认：先给保守默认值、影子模式观察、P1 前做一次小规模标定）
- 决策人：用户 ｜ 记录：Lead ｜ 依据：[.ome/design/memory.md](../../.ome/design/memory.md)、[.ome/research/04-memory-landscape.md](../../.ome/research/04-memory-landscape.md)、[.ome/research/06-repo-seams.md](../../.ome/research/06-repo-seams.md)
- 关联：ADR-0003（项目隔离）、ADR-0004（模型网关）

## 背景

用户要求：记忆分层，模型读抽象概念、底层原始数据作佐证；加入标签与权重，用于区分保存与遗忘；"用户一定要记住的"权重为 1；权重随时间衰减，且权重变化要改变保存周期；需要权重公式与记忆衰竭机制。

调研结论：分层与"抽象+证据"已被货拉拉与腾讯独立实现；显式遗忘公式只有 MemoryBank（`R = e^(−t/S)`，召回 `S+1`）与 Generative Agents（`0.995^小时` 三因子排序）两条线；没有一家把"标签 至 策略"做成完整规则引擎；没有任何方案把 pin 做成一等公民。

## 决策

### D1 五层金字塔与读取规则

L0 证据（原文/工具输出/文件/diff，只存不判）至 L1 情节（会话/步骤/任务摘要）至 L2 原子事实（版本化、可替代）至 L3 概念（偏好/经验/教训/反模式）至 L4 项目与用户画像。

- 模型默认只注入 L4 摘要与相关 L3 概念卡（≤上下文配额 15%）；L2 命中才注入且带 evidence id；L0/L1 永不直接注入，只能通过 `memory.evidence(id)` 下钻；
- 每条注入内容带更新时间、置信度、来源；注入行为写 `memory/recalled` 记录（满足"模型可见即已记录"）。

### D2 标签决定管理策略

标签维度：`type` / `source` / `scope` / `stability` / `sensitivity` / `topic[]`。

- 策略表决定：初始重要性、初始寿命、存储层级、注入优先级、删除与审批要求（表见 [memory.md §3–§4](../../.ome/design/memory.md)）；
- 标签不是分类学装饰；新增标签必须同时给出策略项，否则不允许写入。

### D3 权重与衰竭公式

```text
w(t) = I ， exp(−Δt / S)            pin 至 w ≡ 1，不衰减
I = clamp(type_base × source_mult × confidence)
S = S0 ， (1 + ρ ， n_use) ， conflict_penalty
T_retain = S ， ln(I / θ_archive)
```

- 与半衰期形式 `w = w0 ， 2^(−Δdays/H)` 等价（`H = S ， ln2`）；
- 强化只认"有效使用"：被注入且任务通过、被产物引用且被接受、用户显式确认；被替代的记忆 `S × 0.25` 并标 `superseded`；
- 权重首先是排序偏置，其次才是保留策略：低权重不立即删除，删除由阈值与 TTL 决定。

### D4 保守默认参数

| 参数 | 默认值 |
|---|---|
| `w_floor` | 0.02 |
| `θ_inject` / `θ_warm` / `θ_archive` / `θ_purge` | 0.15 / 0.35 / 0.06 / 0.02 |
| `θ_review` | 0.5 |
| `ρ` | 0.3 |
| `conflict_penalty` | 0.25 |
| `S0`（天） | constraint/decision/anti_pattern 365；preference/procedure 180；fact 60；entity 90；event 30；intention 至截止日；scratch 3 |
| 记忆注入配额 | 上下文 15% |

保守方向：宁可多忘（重新提取便宜），不要让陈旧事实长期留存（误导代价高）；`constraint`/`decision` 例外，长寿命且进入 pin 候选。

### D5 三条删除路径与隐私

- 软遗忘：权重跌破 `θ_archive`，移出默认注入与主检索；
- 归档：长期未用但证据仍在，保留索引低权重条目；
- 硬删除：用户删除或隐私要求，级联删除主记录、派生索引、embedding、缓存与摘要中的直接引用；删除后 60 秒内同一查询不得命中（测试证明）；保留删除审计但不保留内容。

### D6 存储与注入落点

- 主存：`ctx.storageDomain` 独立 `memory` 域（非会话存储），不改会话 JSONL 格式；
- L0 证据存记忆域或 spill，不依赖可能被压缩 `replace` 遮蔽的会话事件；
- 注入：`agent/pre-step` 中 `next()` 之后向 `decision.messages` 追加带来源的 `UserMessage`（先例 `packages/context/agent-instructions`）；备选 `ctx.systemPrompt.context()`；
- 审计事件默认不写；确需写时标 `ignorable: true` 并重生成持久化 catalog、记录类型变更。

### D7 影子模式与标定

- 上线前先跑影子模式（只记录、不注入）≥1 周，对比有/无记忆的差异再开注入；
- P1 出口前做一次小规模标定：只调 `θ_inject`、`S0(fact/preference)`、`ρ` 三个参数，坐标下降 12–15 组，样本 30 条任务 × 3 次；
- 目标函数 `J = 任务通过率 − 0.3 × 记忆 token 占比 − 0.2 × 陈旧事实注入率`；约束：删除彻底性 100%、Recall@8 ≥ 80%；
- 参数版本化、可回滚；留 10 条 held-out 验证防过拟合。

## 备选与不选

| 备选 | 不选理由 |
|---|---|
| 直接接 Mem0/Letta 作为记忆本体 | 写入策略与标签策略正是产品差异点；且厂商自报与独立评测差 45 分，效果不可控 |
| 扁平向量库 + 相似度检索 | 无法表达新旧、衰减、证据链；陈旧率高 |
| 只做文件式记忆（CLAUDE.md 式） | 规模、权重、删除语义不足；作为 L4 索引的补充形式保留 |
| 图谱数据库作为 v0.1 主存 | 收益无独立评测支撑，运维与迁移成本高；先做实体与关联表 |

## 后果与风险

- 收益：跨会话连续、可下钻、可删除、用量可控；标签策略是可差异化的工程能力。
- 代价：写入与睡眠整合的异步管线；参数需要标定；存储与索引两套一致性维护。
- 风险：抽取质量不稳定（缓解：证据约束 + 置信度 + 用户纠正）；参数标定过拟合（缓解：held-out + 影子模式）；隐私删除不彻底（缓解：级联删除测试 + 保留审计元数据）。

## 重议条件

- 自建评测显示记忆对任务通过率无正向贡献（退回"索引文件 + 按需读取"的轻量方案）；
- 出现第三方可复现的跨方案评测证实某现成方案显著更优；
- 隐私法规要求本地可用但禁止任何 embedding 派生副本（需改为纯关键词检索）。
