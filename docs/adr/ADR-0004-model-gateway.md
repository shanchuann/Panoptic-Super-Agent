# ADR-0004：模型网关与分层路由

- 状态：**Accepted**（用户 2026-11-07 确认：Lead/Verifier 用强模型、Worker 可用便宜模型、失败升级；同日确认首版 BYOK，用户自填请求地址与密钥）
- 决策人：用户 ｜ 记录：Lead ｜ 依据：[.ome/DESIGN.md](../../.ome/DESIGN.md)、[.ome/design/projects.md](../../.ome/design/projects.md)、[.ome/research/05-superagent-landscape.md](../../.ome/research/05-superagent-landscape.md)、ADR-0001
- 关联：ADR-0003（项目）、ADR-0005（记忆）

## 背景

基座已有模型适配器 seam（`packages/llm`：`LlmAdapter`、`ctx.llm.registerAdapter`、`listProviders`），每会话在 step 组装前快照 `ModelSelection`。产品需要统一入口：多模型路由、降级、多模态能力声明、用量记录（不计费），以及按角色分配不同档位的模型。用户要求"着重结果，其他交给智能体"，因此成本必须由机制控制，而不是由用户每次选模型。

## 决策

### D1 统一网关入口

- 新增模型网关服务（Host 侧），对外只暴露一个解析步骤：`resolve(request) 至 Spec`。
- `Spec` 至少包含：provider、model、reasoning effort、能力声明（文本/图像/音频/工具调用/缓存/上下文窗口）、超时与重试策略、资源上限（步数/时长）、降级链。
- 网关不重新实现适配器，而是选择并约束基座适配器；请求在 step 组装前完成解析，且 `ModelSelection` 的快照语义不变。

### D2 按角色分层路由

| 角色 | 档位 | 约束 |
|---|---|---|
| Lead（规划/集成/对用户） | 强模型 | 默认档位不可用便宜模型替代 |
| Verifier（验证） | 强模型，优先与执行者不同厂商/家族 | 独立性要求；能用 L0 脚本判定的先走脚本 |
| Builder（执行） | 中档 | 需要工具调用与代码能力；连续失败升级 |
| Researcher / Writer | 便宜档 | 读多写少；产出摘要与结构化内容 |

- 路由输入：角色、任务复杂度（预估步数/上下文长度/工具需求）、资源余额（步数/时长）、历史失败次数；
- 角色档位在角色预设中声明（`model: {tier, name?, effort}`），不在代码里写死；
- 用户可在项目级覆盖模型策略（例如全部使用强模型），覆盖记录在审计中。

### D3 失败升级与降级链

- 升级：同一任务/子任务连续失败 2 次 至 自动升级到强模型重试一次；仍失败 至 转人工或降级方案；
- 降级：主模型超时、限流、鉴权失败、步数/时长超限 至 按 `Spec.fallback` 链切换；切换必须记录原因；
- 降级不得降低安全策略（审批门、只读默认、工具白名单不变）。

### D4 用量记录与资源限制

- 每次模型请求记录：provider、model、输入/输出/缓存 token、耗时、步数、重试次数、调用角色；
- **不计量费用、不展示账单**（用户开发完成后以订阅方式接入模型 API）；
- 资源上限（时长/步数/重试）超限触发 `limit_stopped` 并保留中间产物。

### D5 多模态与能力差异

- 能力差异显式声明在 `Spec`：支持图像输入、音频输入、工具调用格式、缓存、最大上下文；
- 不支持的能力不静默降级为文本：要么选中支持该能力的模型，要么明确报错并给出替代方案。

### D6 首版自带密钥接入（BYOK）

- 首版**不内置供应商账号、不做代计费**：用户在设置页填写 **请求地址（baseURL）+ 密钥（API Key）**，可选自行填写协议类型（Messages-compatible / OpenAI-compatible）与额外请求头白名单。
- 档位映射由用户配置：`strong / medium / cheap` 三档各映射到一个模型 id（同一端点可映射多个模型），路由按角色档位取用。
- 凭据走基座 credentials seam：配置里只存**引用名**，密钥落本地凭据存储（不写进配置文件、不随配置导出）；设置页只显示"已设置/未设置/来源"，永不回显值；轮换后下一次请求即生效。
- 保存前做**连通性测试**：发一次最小请求（模型列表或单 token 补全），失败返回可操作错误（地址错/密钥错/协议不匹配/模型不存在）。
- 安全：密钥不进沙箱、不进日志、错误信息脱敏；baseURL 只允许 `https`（`http://localhost`、`http://127.0.0.1` 例外）；自定义请求头仅允许白名单键。
- 能力声明：按协议给出默认能力（工具调用/图像输入/缓存/上下文窗口），用户可覆盖；能力不足时明确报错，不静默降级。
- 不绑定供应商：档位到模型的映射是配置，可随时改；后续可把常见供应商做成可选预设，但预设不改变 BYOK 的默认路径。
- 订阅接入：用户以订阅方式获得 API（地址 + 密钥），系统不采集价格、不显示金额、不做费用熔断。

## 备选与不选

| 备选 | 不选理由 |
|---|---|
| 由用户在每次对话中手动选模型 | 与"用户只看结果"冲突；错误选择放大用量或质量风险 |
| 全部使用最强模型 | 用量不可控；子智能体 token 放大约 15 倍 |
| 在 adapter 内做路由 | 与基座 seam 语义冲突，且无法统一计量与审计 |
| 引入外部模型网关服务 | 多一个故障点与数据外发面；v0.1 本地优先 |

## 后果与风险

- 收益：用量与质量可分层控制；角色档位可配置；降级可观测；验证独立性有制度保障。
- 代价：需要维护能力声明与路由规则；多模型组合增加测试矩阵。
- 风险：便宜模型的工具调用与长上下文能力不足（缓解：按角色做能力门槛与 A/B）；跨厂商验证增加账单与合规面（缓解：只对验证角色启用）；许可冲突（Claude Agent SDK 许可未定论，本项目只借范式不引代码）。
- BYOK 风险：用户填错地址或协议导致不可用（缓解：连通性测试与清晰错误）；密钥泄露（缓解：凭据存储、日志脱敏、不进沙箱）；用户选到能力不足的模型（缓解：能力声明与运行前校验）；端点可用性由用户负责（缓解：降级链与明确失败提示）。

## 重议条件

- 单模型能力足够且资源可控（可简化为单档 + 缓存）；
- 出现统一的能力协商标准（跨供应商）；
- 验证独立性被证明可由同一模型的不同提示/工具保证。
