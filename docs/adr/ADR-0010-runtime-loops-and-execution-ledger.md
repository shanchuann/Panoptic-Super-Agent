# ADR-0010：运行循环、执行账本与能力授权

- 状态：**Accepted**（2026-11-08 依据 v1.1 设计评审与技术路线报告修订）
- 决策人：项目组 ｜ 记录：Lead ｜ 依据：[manual.md](../../.ome/manual/manual.md)、[.ome/contracts](../../.ome/contracts/README.md)、[ADR-0006](ADR-0006-collaboration-model.md)、[ADR-0007](ADR-0007-evolvability-contract.md)
- 关联：ADR-0003（项目域）、ADR-0005（记忆）、ADR-0009（事件运行时）

## 背景

v1.1 设计已经明确项目域、事件日志、上下文包、五层记忆、能力契约与验证优先。外部评审与工程报告指出六个需要修正的结构性问题：项目生命周期与日常交互耦合过紧；任务状态与知识状态未充分解耦；记忆权重承担了过多职责；上下文压缩缺少保真契约；工具权限表述存在冲突；第一阶段范围仍然偏大。

工程报告同时建议保留 DeepSeek Harness 作为 Runtime，不引入 LangGraph、Temporal、A2A 或 Mem0 作为核心，补上执行账本、能力授权与可观测性。

## 决策

### D1 三个独立循环共享项目状态

- **交互循环**：接收自然语言，判断直接回答、创建任务、修改任务或澄清；日常问答不进入正式生命周期。
- **执行循环**：任务规划、工具调用、检查点、重规划与验证。
- **学习循环**：从事件、产物与运行结果中抽取、合并、失效与遗忘记忆。
- 三者共享项目状态，但生命周期独立。只有需要执行或修改项目的意图才创建任务。

### D2 交互路由器

- 输出四类：直接回答、创建任务、修改任务、请求澄清。
- 规则优先；置信度低时用小模型分类；每次分类记录类型、依据与决策者。
- 任务型请求必须带目标与至少一条验收判据，否则进入问询而不是直接建任务。

### D3 执行账本与幂等语义

- 每个有副作用或可能产生副作用的工具调用生成执行记录：执行标识、工具标识、幂等键、输入哈希、状态、开始与提交时间、结果引用。
- 语义为 **至少一次执行 + 副作用幂等 + 持久执行账本**，不承诺工具调用恰好一次。
- 已提交的执行记录在恢复时直接返回结果；未提交的记录按工具策略检查或重试。

### D4 检查点与恢复

- 运行检查点记录：运行标识、任务标识、步骤、上下文版本、计划版本、已执行与待执行工具、产物、审批状态、记忆快照版本。
- 崩溃恢复策略：模型调用可重复；只读工具通常可重复；有副作用的工具先查账本。
- 任务恢复后必须能回答已完成、未完成、下一步与证据位置。

### D5 能力授权模型

- 授权对象为使用者、执行体或单次运行；授权范围包括项目、能力、资源路径或域名、有效期、调用次数与字节上限。
- 项目工作区内、已授权范围内的写操作可以连续执行；越界写、不可逆操作与对外发送仍需审批。
- 权限判断在可信代码中完成，不由模型决定；工具调用先校验结构，再查授权，再判定风险与审批。

### D6 可观测性

- 采用 OpenTelemetry 统一追踪项目请求、任务运行、上下文装配、记忆检索、模型调用、工具执行、验证与记忆整合。
- 记录标识、模型、令牌数、工具、风险、审批、耗时与重试次数。
- 默认不记录完整提示词、工具原文、密钥与个人敏感信息。

### D7 存储策略

- 第一阶段本地优先，沿用存储域与 SQLite，向量检索先用本地扩展或轻量索引。
- PostgreSQL 与 pgvector 作为后续多设备或大数据量阶段的选项，不作为第一阶段强制依赖。
- 记忆、项目与上下文契约与存储后端解耦，后端替换不影响语义。

### D8 延后项

- Temporal、A2A、Graphiti 类时序图记忆、Mem0 作为核心记忆引擎，均不进入第一阶段。
- 保留适配器接口，后续按真实需求评估。

### D9 第一阶段发布门槛

- 必须通过“创建项目、修改代码、崩溃、重启、恢复、继续、验证、记忆整合”的端到端演示。
- 同一副作用不得重复提交；验收不得仅由模型自述完成。

## 备选与不选

| 备选 | 不选理由 |
|---|---|
| 用 LangGraph 替换 Runtime | 与现有 Harness 的循环、会话、工具重复，迁移成本高于收益 |
| 直接引入 Temporal | 第一阶段没有小时级后台工作流，引入成本高；Activity 副作用仍需幂等 |
| 以 Mem0 作为记忆核心 | 数据模型与项目语义不匹配；可作为抽取适配器，不作权威 |
| 只做写文件全部确认 | 阻断连续编码，用户无法在已授权工作区内正常工作 |
| 只做项目生命周期 | 日常问答被迫走正式流程，交互僵硬 |
| 承诺工具调用恰好一次 | 外部系统无法普遍保证，只能做到至少一次加幂等 |

## 后果与风险

- 收益：日常交互与项目执行分离；恢复与副作用去重有明确语义；权限可授权、可审计；记忆与任务状态解耦。
- 代价：新增交互路由、执行账本、授权与追踪四块工程；数据模型增加标识与版本字段。
- 风险：路由器误分类（用规则优先与人工覆盖）；账本膨胀（按项目归档与清理）；授权粒度过细（提供项目级默认授权）。

## 重议条件

- 执行账本维护成本超过收益时，收缩为仅覆盖外部副作用工具；
- 出现稳定且被广泛采用的工作流引擎或 Agent 互操作标准时，重新评估 Temporal 与 A2A；
- 本地存储无法支撑数据量时，迁移到 PostgreSQL 与 pgvector。
