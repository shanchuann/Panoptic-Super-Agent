# ADR-0009：事件驱动运行时与 Watchdog

- 状态：**Accepted**（用户 2026-11-07 希望接入工作流/项目运行时：有人提出问题，智能体自己修、自己测、自己推送）
- 决策人：用户 ｜ 记录：Lead ｜ 依据：[runtime.md](../../.ome/design/runtime.md)、Super-agent 六特性分析（用户提供）、[extensibility.md](../../.ome/design/extensibility.md)
- 关联：ADR-0006（协作）、ADR-0007（可演进）、ADR-0008（生命周期）

## 背景

用户提供了 DeepSeek Super-agent 的技术解析：双层架构（Router + Worker）、事件驱动、订阅直通、全双工、存算分离、Watchdog。希望本产品也能在项目运行时中"被事件唤醒并自主修复/测试/推送"。

## 决策

### D1 触发器服务

- 来源：项目事件、IM、GitHub issue/PR/comment、CI 失败、定时、Webhook；
- 流程：规则层过滤（白名单/签名/去重/限流）至 模型分诊（是否执行/归属项目/优先级）至 Router 派发 至 Run 执行 至 回写；
- 每个触发器带预算、审批策略与审计；来源默认 untrusted。

### D2 Router / Worker 双层

- Router = 规则 + 轻量模型：分诊、归属、派发、订阅管理，不做重活；
- Worker = Run/Subagent：强模型执行任务；
- 与协调策略层的分工：Router 负责"事件至任务"的入口分诊，协调策略层负责"任务至拓扑"的选择。

### D3 订阅与直通

- Worker 可订阅后续相关事件（同一 PR/话题/失败）；
- 后续事件直达 Worker，减少 Router 重复判断；
- 订阅有过期、退出条件与治理约束（审批/预算/写域不豁免）。

### D4 全双工

- Run 异步执行，前台对话不阻塞；支持插话、暂停、取消、追加要求；
- 收件箱承接需要人的事项；长任务 checkpoint 可恢复。

### D5 Watchdog

- P1 进程内（guard 插件）：心跳、死循环、无进展、预算接近上限；
- P1.5 起独立 watchdog 服务：外部视角检查，避免被监控进程本身失效；
- 只允许暂停/升级/告警，不能替代审批与验收；方向偏移用 Brief/判据做模型评审。

### D6 存算分离（预留）

- 形态：云端会话/记忆/项目状态 + 本地或远程执行器 adapter（RPC/WebSocket）；
- 约束：密钥只在执行端、传输加密、设备配对与撤销、默认关闭；
- 阶段：P2 评估，不阻塞 P1；接口先按 adapter 预留（ADR-0007）。

### D7 安全边界

- 外部触发器不可信：未签名/非白名单直接拒绝；
- "自己推送"属于外发动作，必须审批或项目级显式授权；
- 自动修复受写域、预算、测试门禁约束，不因自动而降低标准。

## 备选与不选

| 备选 | 不选理由 |
|---|---|
| 只做用户手动触发 | 无法响应 PR/CI/群消息，失去主动能力 |
| 触发器直接驱动强模型执行 | 成本高、误触发多；必须规则过滤 + 分诊 |
| Router 用强模型 | 分诊频率高、成本高；轻模型足够 |
| 自己实现存算分离 | 复杂且 P1 无需求；先留 adapter |
| Watchdog 直接改任务状态 | 权限过大、易误伤；只暂停/升级/告警 |

## 后果与风险

- 收益：从被动到主动；长任务不阻塞对话；自动发现跑偏。
- 代价：触发器与订阅的治理复杂度；watchdog 误报；远程运行时的安全面。
- 风险：触发器洪泛（限流/去重）；误触发导致成本（预算/审批）；自动推送的风险（审批门 + 白名单）。
