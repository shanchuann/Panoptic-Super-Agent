## 1. 产品定义

**一句话**：用户创建一个项目，用自然语言说出目标，智能体自行完成澄清、规划、任务安排、分工执行、验证与交付；跨会话记得住人、项目和经验。

**产品形态**：开源（MIT）、个人自用、自带 API 密钥（BYOK）；无多租户、无计费、无云端账号，所有状态与数据在本机。

**默认界面是项目进度图，不是聊天窗口**：图展示任务、依赖、并行、阻塞与产物；点击节点才展开该节点的结果与聊天记录。用户关注结果，过程默认折叠（见 [interaction.md](design/interaction.md)）。

与聊天机器人的分界：
- 有项目容器与结构化状态（不是一次性对话）；
- 有交付物（版本化、可预览、可回滚、可溯源）；
- 有验证闭环（判据 + 证据，而不是"我说完成了"）；
- 有长期记忆与上下文用量控制；
- 有安全边界与资源上限。

不做（v0.1，见 SCOPE §2）：通用聊天、多租户 SaaS、自研模型、插件市场、开放桌面 GUI 自主操作、移动端、私有化部署。

## 2. 设计原则（冲突时的裁决顺序）

1. **先证据，后结论**：任何事实性记忆都能下钻到原始证据；没有证据的"事实"不进长期记忆。
2. **上下文是配额，不是仓库**：所有注入都受配额约束；能放句柄就不放原文。
3. **状态外置、事件追加**：会话与项目状态都可重放；压缩只生成视图，不删除事实。
4. **统一执行契约**：内置工具、MCP、代码执行、子智能体同构为 `execute(name, input) 至 result`。
5. **能力即 seam**：记忆、模型、工具、沙箱、项目各由 Service Definition / Provider / Consumer 三角构成，后端可换。
6. **默认只读、越权必审批**：写、付款、外发三类动作强制人工确认；不可信内容不得直接驱动高危工具。
7. **模型可见 等价于 已记录**：任何进入模型请求的内容必须能从会话/记忆事件重建。
8. **外部验证优先于自我反思**：用测试、schema、工具返回校正；模型自评只作参考。
9. **资源与停止条件是机制**：时长/步数/重试上限、停止条件不依赖提示词自律（不计量费用）。
10. **能力可验收**：每个模块有可执行判据与证据；没有判据的功能不算完成。

## 3. 总体架构

```text
┌──────────────────────────────────────────────────────────────┐
│ 交互层   项目图谱（默认）， 节点详情，收件箱，CLI/SDK        │
├──────────────────────────────────────────────────────────────┤
│ 项目层   Project，Brief，Goal，Task DAG，Artifact，Audit │
│          （黑板=项目域，协作状态唯一权威）                     │
├──────────────────────────────────────────────────────────────┤
│ 协调策略层 模式选择，上下文包路由，决策审计                  │
├──────────────────────────────────────────────────────────────┤
│ 会话层   Session（append-only 事件日志）， 投影，回放          │
├──────────────────────────────────────────────────────────────┤
│ 编排层   Agent Loop，规划，Todo，子智能体，调度，停止条件 │
├──────────────────────────────────────────────────────────────┤
│ 上下文层 组装，配额，压缩(C0–C4)，溢出，记忆注入           │
├──────────────────────────────────────────────────────────────┤
│ 记忆层   L0 证据 至 L1 情节 至 L2 事实 至 L3 概念 至 L4 画像      │
│          标签策略，权重/衰减，睡眠整合，删除级联            │
├──────────────────────────────────────────────────────────────┤
│ 工具层   execute()，权限/审批，MCP，PTC，沙箱             │
├──────────────────────────────────────────────────────────────┤
│ 模型层   网关：路由，降级，多模态，用量记录                 │
├──────────────────────────────────────────────────────────────┤
│ 治理层   资源限制，审计，安全策略，评测                     │
└──────────────────────────────────────────────────────────────┘
```

端到端一次任务的流转：

```text
用户："做 X"
 至 项目层：建项 / 澄清 / Brief / 计划（任务 DAG）
 至 编排层：分配任务 至 主智能体 + 子智能体执行
 至 上下文层：按配额组装（项目状态 + 记忆卡 + 工具结果摘要）
 至 工具层：执行工具（审批/沙箱）至 结果压缩/溢出
 至 记忆层：异步抽取事实、更新权重、睡眠整合
 至 编排层：验证器按判据验证 至 产物入库
 至 项目层：里程碑/交付 至 用户验收 至 迭代
 至 全程：会话事件 + 项目审计 + 用量记录（不计费）
```

v1.2 在状态层加入执行账本，在能力层加入能力网关，在保障层加入可观测性。执行账本保存副作用记录与检查点，能力网关统一授权与审批，可观测性追踪项目到工具的完整链路。

### 3.1 三个运行循环

系统内部有三个生命周期独立的循环，共享项目状态。

| 循环 | 输入 | 输出 | 生命周期 |
|---|---|---|---|
| 交互循环 | 用户自然语言、项目状态 | 直接回答、创建任务、修改任务、澄清请求 | 单轮或短会话 |
| 执行循环 | 任务、上下文包 | 运行、产物、证据 | 跨步骤，可暂停恢复 |
| 学习循环 | 事件、产物、运行结果 | 记忆写入、合并、失效、删除 | 异步批处理 |

日常问答只经过交互循环，不创建任务。只有需要执行或修改项目的请求才进入任务阶段。执行循环负责规划、工具调用、检查点与验证。学习循环负责把结果沉淀为记忆。

## 5. 三处内容层重构（用户点名）

### R-MEM 记忆子系统（详见 memory.md）
- 从"会话日志 + 压缩"扩展为五层记忆金字塔；
- 关键创新：标签决定管理策略、权重公式决定保留周期、睡眠整合维护长期质量；
- 存储独立于会话 JSONL（不动已发布格式），通过事件关联。

### R-LLM 模型网关（ADR-0004 待写，本文只定边界）
- 统一入口：`resolve(request) 至 Spec`（路由、模型、多模态能力、资源上限）；
- 能力差异显式声明：文本/图像/音频/工具调用/缓存/上下文窗口；
- 降级链：主模型超时/限流/步数超限 至 备选模型 至 降档提示；
- 用量：每请求 token/步数落事件，供资源限制与诊断展示（不计费）。

### R-SESS 会话与项目（ADR-0003 待写）
- 会话仍是 append-only 事件日志与执行轨迹；
- 新增项目层作为业务状态容器，项目事件引用会话事件；
- 目标驱动连续工作：Goal + Round Driver + 停止条件（时长/步数/无进展/用户暂停）。

## 9. 验收与评测

- 能力验收：各模块文档的判据表（memory §13、projects §13、context §9、tools §10）；
- 项目级评测：基线 20 条 held-out（P1 出口扩到 30 条）+ 五项指标（完成率、pass^k、接管率、P95 时长、用量诊断）；
- 安全评测：≥5 条攻击用例（直接注入、间接注入、工具投毒、越权读取、外发回连）必须全拦截；
- 记忆专项：抽取准确率、召回率、陈旧率、删除彻底性、token 节省。

| 风险 | 影响 | 缓解 |

| 记忆子系统复杂度高 | 延期、效果不达预期 | 分 M1–M4 交付，先文件式最小闭环 |
| 权重公式参数难校准 | 该记的忘了/该忘的还在 | 参数可配置 + 评测驱动调参 + 用户纠正入口 |
| 项目状态与会话状态双写不一致 | 状态漂移 | 单一写入口 + 事件溯源 + 对账任务 |
| 子智能体资源失控 | 时长/步数超支 | 并发上限 + 每任务资源上限 + 硬熔断 |
| 品牌替换遗漏 | 合规风险 | R-005 清点清单 + 截图对比 |
| 上游不跟进 | 安全补丁滞后 | 高危漏洞人工评估 cherry-pick |
