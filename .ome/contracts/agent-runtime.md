# Agent Runtime 契约

## 目的

定义交互、执行、学习三个循环的边界，以及运行、检查点、工具调用与恢复的语义。

## 循环

| 循环 | 输入 | 输出 | 生命周期 |
|---|---|---|---|
| 交互 | 用户自然语言、项目状态 | 直接回答、创建任务、修改任务、澄清请求 | 单轮或短会话 |
| 执行 | 任务、上下文包 | 运行、产物、证据 | 跨步骤，可暂停恢复 |
| 学习 | 事件、产物、运行结果 | 记忆写入、合并、失效、删除 | 异步批处理 |

三个循环共享项目状态，不共享进程内状态。

## 运行状态

运行经历排队、准备、执行、暂停、成功、失败、资源停止、取消与超时。暂停与取消必须传播到子进程与工具执行。

## 检查点

检查点至少包含：运行标识、任务标识、步骤、上下文版本、计划版本、已执行工具、待执行工具、产物、审批状态、记忆快照版本。

检查点在以下时点写入：每个工具调用完成后、每次模型请求前、暂停与取消时。

## 工具调用与账本

每个有副作用的调用生成执行记录：执行标识、工具标识、幂等键、输入哈希、状态、开始时间、提交时间、结果引用。

状态包括待执行、执行中、已提交、失败、未知。未知状态必须人工或策略判定，不能直接重试。

## 恢复算法

1. 读取最近检查点与执行账本。
2. 已提交的副作用直接返回结果。
3. 执行中或未知的记录按工具策略检查，确认未提交后才允许重试。
4. 只读工具与模型调用可以重复。
5. 恢复后输出已完成、未完成与下一步。

## 取消与暂停

取消立即停止新的模型与工具调用，等待在途调用收敛。暂停保留检查点并释放执行资源。两者都写入审计。

## 验收

崩溃前后各杀进程一次，恢复后不重复已提交副作用；取消后无孤儿进程；检查点可重放。
