日期：2026-11-08　处理人：项目组

## 部分采纳

- 存储：报告建议 PostgreSQL 加 pgvector 作为默认。第一阶段仍本地优先，沿用存储域与 SQLite；PostgreSQL 作为后续多设备或大数据量的选项。契约与后端解耦。
- 记忆权重：评审建议拆开有效性、相关性、保留与热度。已改为权重只负责排序与注入，删除由有效性、保留策略与隐私要求决定。
- 用户钦定：pin 只表示保留承诺，不表示事实永远正确；被替代或标记无效时仍提示冲突。
- 交互路由：采纳分类思路，但先做规则优先，模型只处理低置信度区间；分类准确率需要自有样本验证。

## 不采纳

| 建议 | 理由 |
|---|---|
| 用 LangGraph 或 Microsoft Agent Framework 替换 Runtime | 与现有 Harness 的循环、会话、工具重复，迁移成本高于收益 |
| 第一阶段引入 Temporal | 没有小时级后台工作流；Activity 副作用仍需幂等 |
| 以 Mem0 作为记忆核心 | 数据模型与项目语义不匹配；可作为抽取适配器 |
| 引入 Graphiti 类时序图记忆 | 第一阶段复杂度高，收益缺少自有验证 |
| 承诺工具调用恰好一次 | 外部系统无法普遍保证，改为至少一次加幂等 |
| 第一阶段强制 PostgreSQL | 与本地优先定位冲突；先保证单机可用 |

## 仍待验证

1. 交互路由分类准确率需要 20 条以上标注样本。
2. 执行账本与恢复需要真实崩溃演练，当前只有设计。
3. 记忆作用域隔离与删除彻底性需要测试证明。
4. 能力授权的实际粒度是否足够，需要按真实项目试用。
5. 上下文装配比例的基准测试尚未建立。
