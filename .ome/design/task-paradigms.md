# 任务范式路由：不同任务用不同开发方式

> 状态：设计草案 ， 2026-11-07 ， 上位：[.ome/DESIGN.md](../DESIGN.md)、[ADR-0008](../../docs/adr/ADR-0008-lifecycle-and-paradigms.md)、[ADR-0006](../../docs/adr/ADR-0006-collaboration-model.md)
> 一句话：**任务类型决定“怎么做”（playbook），任务规模与证据决定“谁来做、并行多少”（拓扑）**；两者组合，而不是一个 loop 走天下。

## 0. 两个维度不要混

| 维度 | 回答 | 决定者 |
|---|---|---|
| 任务范式（Paradigm） | 这类任务的标准做法、工具、技能、验收方式 | 任务类型注册表 |
| 协作拓扑（Topology） | 单 agent / 协调者 / 黑板 / 流水线 / 两级扇出 | 协调策略层（ADR-0006，按规模与证据） |

例：同一份“竞品分析”既可能是 solo（一条链跑完），也可能是 blackboard（多源并行）；范式相同，拓扑不同。

## 1. 任务类型注册表（P1 预置六类）

| 类型 | 标准步骤（playbook） | 默认工具 | 预置技能 | 主要验收 | 默认拓扑 |
|---|---|---|---|---|---|
| research 调研 | 澄清问题 至 多源检索 至 交叉验证 至 结构化结论 至 来源清单 | web/fs/read | 检索、引用纪律、对比表 | 来源可点、结论有证据 | M1（可扇出） |
| code 代码 | 读现状 至 定位 至 最小改动 至 测试 至 回归 至 diff 说明 | fs/shell/ptc | 代码规范、测试、迁移 | 测试转绿 + 回归 | M1/M2 |
| doc 文档 | 大纲 至 素材 至 初稿 至 校对 至 来源/术语表 | fs/read | 写作、排版、去 AI 味 | rubric + 来源 | M0/M1 |
| data 数据 | 读入 至 清洗 至 计算/建模 至 校验 至 图表/表 | fs/ptc | 表格、校验、图表 | 公式/口径可复核 | M1 |
| design 设计 | 需求 至 参考 至 方案/原型 至 评审 至 交付 | fs/browser | 控件选型、视觉、合规 | 走查表 + 截图 | M1 |
| ops 运维 | 诊断 至 变更计划 至 执行 至 验证 至 回滚点 | shell/ssh/schedule | 发布/回滚/监控 | 冒烟 + 回滚演练 | M1/M3 |

每类范式包含：默认步骤、工具白名单、技能集、验收器、默认拓扑、常见反模式。

## 2. 路由怎么发生（规则优先 + 模型判断）

~~~text
任务进入 至 规则分类（关键词/文件类型/仓库/项目类型）
  至 置信度低 至 小模型分类（输出类型 + 理由）
  至 绑定 playbook + 技能集
  至 协调策略层按规模/证据选拓扑
  至 写入任务审计（type, playbook, mode, rationale）
~~~

- 类型判断错误可人工覆盖（项目级/任务级），覆盖写审计；
- 混合任务拆分为多个类型化子任务（例如“调研 + 写页面”= research + design/code），由 Lead 归并；
- 新类型 = 注册 playbook + 验证器 + 技能集，不改内核（ADR-0007）。

## 3. 技能预设（可插拔、可删除）

| 技能包 | 覆盖 | 形态 |
|---|---|---|
| 文本写作 | 大纲、润色、去 AI 味、术语一致 | skill 包 |
| 表格/数据 | xlsx/csv、公式、校验、图表 | skill + 工具 |
| 图像/视觉 | 生成、编辑、截图理解 | tool provider + skill |
| 前端设计 | 控件选型、组件、响应式、合规审查 | skill 包 |
| 后端/接口 | 契约、数据模型、迁移、测试 | skill 包 |
| 代码管理 | git 工作流、PR、评审、发布 | skill + 工具 |

规则：技能默认按项目/任务类型启用；**可单独安装/卸载/禁用**；卸载后不影响内核；技能版本随项目锁定（可复现）。

## 4. 与“模型驱动”的关系

- 模型负责：理解目标、判断任务类型、选择 playbook、处理异常；
- 规则负责：类型注册表、工具白名单、验收判据、拓扑门槛（D9），不让模型自由发明流程；
- 可解释：每次路由记录 type/playbook/mode/rationale，用户可在节点详情查看。

## 5. 验收判据

| # | 判据 | 标准 |
|---|---|---|
| P1 | 类型识别 | 20 条标注任务类型识别 ≥85% |
| P2 | playbook 生效 | 同类任务步骤一致率 ≥80%（抽样） |
| P3 | 技能可插拔 | 卸载任一技能包后任务可降级运行，不崩 |
| P4 | 路由可解释 | 审计含 type/playbook/mode/rationale |
| P5 | 混合任务 | 拆分正确率 ≥80%（人工复核） |
