# Panoptic Super 上下文管理设计（v0.2 草案）

> 状态：设计草案 v0.2 ， 2026-11-07（按 07 调研复核补充：工具目录段、折叠优先、缓存契约、上下文包字段）， 上位文档：[.ome/DESIGN.md](../DESIGN.md)
> 一句话：上下文不是"把能塞的都塞进去"，而是按配额组装一个**可解释、可压缩、可回溯**的工作集；压缩只压缩视图，不销毁事实。

## 0. 问题

1. **用量主变量是上下文，不是模型**：输入/输出比高、缓存与非缓存单价差距大（但本项目不计量费用，只控制用量）；历史越长每轮越贵。
2. **上下文腐化（context rot）**：无关内容越多，关键约束越容易被忽略；长上下文≠有效上下文。
3. **工具结果是最大膨胀源**：搜索结果、日志、代码、错误栈往往是几百 K token。
4. **压缩不可逆会丢证据**：摘要丢了细节，事后无法复核；必须"视图可压缩、事实不删除"。

## 1. 上下文组装模型

每轮请求的上下文由固定顺序的段（section）组成，每段有配额与来源：

| # | 段 | 内容 | 默认配额 | 可变性 |
|---|---|---|---|---|
| S0 | 工具目录 | 当前可用工具的名称 + 一行说明（完整 schema 按需注入） | 5% | 半稳定（工具集变化时重写） |
| S1 | 身份与规则 | 系统提示、安全规则、输出规范 | 5% | 稳定（利于 prompt cache） |
| S2 | 项目章程 | Brief：目标/非目标/成功判据/约束 | 8% | 稳定（变更需记录） |
| S3 | 项目状态 | 当前里程碑、任务 DAG 摘要、阻塞项 | 7% | 每轮变 |
| S4 | 记忆注入 | L4 画像 + L3 概念卡 + 必要 L2 事实 | 15% | 每轮检索 |
| S5 | 工作集 | 当前任务目标、计划、待办、验收判据 | 10% | 每轮变 |
| S6 | 对话近况 | 最近 N 轮用户/助手消息 | 20% | 滑动窗口 |
| S7 | 工具结果 | 本轮工具返回的压缩视图 | 15% | 每轮变 |
| S8 | 输出预留 | 模型生成所需空间 | 15% | 固定 |

配额按模型窗口与任务类型配置，不写死；总和超限时按 §4 降级顺序裁剪。

### 1.1 组装流水线

```text
读取项目状态与任务状态
  至 检索记忆（scope 过滤 + 三路召回 + 排序，见 memory.md）
  至 生成各段候选内容
  至 去重（同一事实不在多段重复出现）
  至 标注（来源、更新时间、置信度、不可信标记）
  至 按配额分配与裁剪
  至 稳定前缀前置（S1–S2）以命中缓存
  至 写入 session 事件（context/assembled 摘要，非全文）
```

规则：
- **prompt 布局契约**：稳定前缀（S0 工具目录 + S1 身份 + S2 项目章程）严格逐字不变；所有动态内容（检索结果、工具结果、时间戳）放在末尾；缓存断点只打在前缀边界；记录 `cache_read_tokens` 与"缓存断裂"事件；
- **工具目录按需渐进披露**：S0 只放名称与一行说明；完整 schema 命中后才注入；工具定义 token 数单独打点（Anthropic 实测工具定义可达 134K tokens，Tool Search 后开工占用 77K至8.7K）；
- **稳定段在前、动态段在后**：S0–S2 尽量逐字稳定，提高 prompt cache 命中；
- **单一来源**：同一条事实只出现在一个段（优先记忆段），避免重复占配额；
- **元数据随行**：每条外部内容带 `source`、`updated_at`、`trust`（trusted/untrusted）；
- **可解释**：任何一段被裁剪/注入都能回答"为什么"（记录规则与分数）。

## 2. 分层压缩

压缩是"生成更小的视图"，不是"删除底层数据"：

| 级别 | 输入 | 输出 | 触发 | 保留 |
|---|---|---|---|---|
| C0 原始 | 工具结果/消息 | 原文 | 产生时 | 落文件/事件，永不因压缩删除 |
| C1 步骤压缩 | 单步工具结果 | 摘要 + 句柄（`ref://`） | 结果超阈值（按模型窗口比例，默认 2%，并按工具类型分档；标 D 待校准） | 关键字段、错误、路径、结论 |
| C1.5 折叠 | 子任务分支（子 Run） | 结论 + 判据 + 句柄 + parent/child 指针 | 子任务完成或超预算 | 子会话保留，父只留折叠节点（活跃上下文小 10×，优于摘要压缩） |
| C2 情节压缩 | 一段多步执行 | 步骤摘要序列 + 决策点 | 超出窗口或任务结束 | 决策、失败、产物、证据指针 |
| C3 会话摘要 | 整个会话 | 项目级摘要 | 会话结束/切换 | 结论、未决项、产物 |
| C4 项目摘要 | 项目全过程 | 交付说明 + 决策日志 | 里程碑/交付 | 目标达成情况、关键取舍 |

**顺序原则**：折叠（C1.5）是主路径，摘要压缩（C2–C4）是兜底；只有在无法折叠时才升级到有损压缩。

### 2.1 压缩后必须重建的工作集（不可裁剪项清单）

以下内容压缩时不得丢弃：验收判据、用户约束、活动决策、未完成步骤、失败原因、审批状态、产物引用、检查点引用。其他内容可以按优先级裁剪。

压缩契约详见 [context-assembly.md](../contracts/context-assembly.md)。

压缩不是"扔掉一半上下文"，而是**重建一个最小可用工作集**。每次压缩后逐项恢复：

1. 系统提示与安全规则（S1）；
2. 项目 Brief / 常驻指令（S2）；
3. 项目记忆索引（`MEMORY.md` 一行式）+ 本轮必需的记忆卡（S4）；
4. 当前计划与待办（S5）；
5. 技能/工具索引（只放名称与一行说明，正文按需加载）；
6. 最近修改/查看的文件清单（路径 + 一句变更说明）；
7. 已加载技能/文档的正文（按配额裁剪，单条与总量都有上限）；
8. 后台任务/子智能体的状态摘要（不重放日志）。

原则：压缩丢的是"过程"，保留的是"接下来要用的状态 + 判断依据"。缺失项会导致模型重复劳动或违反约束。

### 2.2 上下文包（Context Packet）与 Context Broker

协作进化后，Worker 不再继承父会话历史，而是由 **Context Broker** 按任务组装上下文包：

```ts
interface ContextPacket {
  taskId: string;
  goal: string;                       // 任务目标（一句话）
  acceptance: AcceptanceCriterion[];  // 验收判据
  artifacts: ArtifactRef[];           // 相关产物 + 句柄
  memory: MemoryCard[];               // 检索到的记忆卡（带 id/置信度/时间）
  recentEvents: EventSummary[];       // 最近相关事件摘要（不是全量）
  decisions: DecisionRef[];           // 已确认的决策（共享决策，不共享轨迹）
  assumptions: string[];             // 未言明的假设（子任务必须看到）
  forbidden: string[];               // 禁止事项 / 约束
  upstreamDiffRef?: string;          // 上游改动的 diff 句柄（代码类任务）
  quota: { tokens: number };          // 本包配额
  provenance: string[];               // 每个片段的来源（可下钻）
}
```

规则：
1. **按需拉取**：Broker 从项目域、产物库、记忆域、事件日志取数据，不读父会话全文；
2. **配额化**：超过配额按优先级裁剪（判据 > 约束 > 产物 > 事件 > 背景），裁剪记录在案；
3. **可解释**：每个片段带来源 id，模型可见即可追溯；
4. **可复现**：同样的任务与状态生成同样的包（时间戳与随机源固定）；
5. **句柄优先**：大结果只给句柄，模型按需下钻。

Context Broker 是服务而非 Agent：无模型调用、无对话，纯组装与裁剪；失败时降级为最小包（目标 + 判据）并告警。

装配请求包含项目标识、任务标识、运行标识、目标、判据、模型窗口、预算、记忆作用域与所需能力。每次装配生成上下文版本号，可重放。契约见 [context-assembly.md](../contracts/context-assembly.md)。

**上下文包的一生（组装 至 注入 至 折叠 至 回写）**

1. **请求**：任务进入 ready（或 Run 启动）时，向 Broker 发 `compose(taskId, phase)`；
2. **取数**：从项目域取任务/判据/决策/假设/禁止事项，从产物库取相关产物句柄，从记忆域按任务检索概念卡，从事件日志取最近摘要；
3. **裁剪**：按优先级（判据 > 约束/决策 > 产物 > 事件 > 背景）装包，超配额则截断并记录；
4. **注入**：作为一条带来源的 `UserMessage` 进入该 Run；Worker 不继承父会话历史；
5. **执行中**：需要细节时按句柄下钻（`memory.evidence` / 文件读取），不把原文塞回上下文；
6. **折叠**：Run 结束时把过程折叠为"结论 + 判据 + 证据 + 句柄"，父侧只接收折叠结果（C1.5）；
7. **回写**：结果写项目域（任务状态、产物、证据、审计），供下一次组装复用。

**示例（研究类任务）**

~~~json
{
  "taskId": "task_042",
  "goal": "对比三家 AI 笔记产品的定价与功能，输出一页结论",
  "acceptance": [{ "kind": "exec", "spec": "report.md 含 3 条带日期来源链接" }],
  "artifacts": [{ "id": "art_17", "kind": "doc", "handle": "ref://art_17" }],
  "memory": [{ "id": "mem_88", "card": "用户偏好中文、结论先行", "confidence": 0.85, "updatedAt": "2026-11-02" }],
  "decisions": [{ "id": "dec_3", "text": "只做公开资料，不登录抓取" }],
  "assumptions": ["竞品价格以官网为准"],
  "forbidden": ["不采集登录后数据"],
  "recentEvents": [{ "seq": 1201, "summary": "已收集 5 个来源" }],
  "quota": { "tokens": 12000 },
  "provenance": ["project_7", "mem_88", "art_17"]
}
~~~

**失败模式**：包过大（按优先级截断并记录）；记忆冲突（注入前去冲突，同主谓只留最新）；产物句柄失效（回退到重建索引）；Broker 不可用（降级最小包并告警，任务不阻塞）。
约束：
- 每个压缩产物带 `source_event_ids`，可反查原文；
- 压缩后的内容若被模型引用，必须保留指针，保证"模型可见 ⟺ 可回溯"；
- 压缩质量纳入评测：抽样人工比对关键信息保留率。

## 3. 工具结果治理

| 策略 | 何时 | 做法 |
|---|---|---|
| 截断 | 输出超阈值 | 保留头部+尾部+关键行，中间折叠 |
| 结构化提取 | 有 schema 的结果 | 只取字段（路径、错误码、计数） |
| 溢出落盘 | 大结果（日志/HTML/代码） | 全文写文件，上下文只留摘要 + 句柄 |
| 代码执行编排（PTC） | 多步数据处理 | 中间结果留在沙箱，只回最终结论，减少往返与 token |
| 不可信标记 | 网页/文档/MCP 返回 | 标记 `trust=untrusted`，禁止直接驱动高危工具 |

原则：**上下文里放"结论 + 句柄"，不放"原材料"**；需要细节时按句柄取。

## 4. 配额与降级

触发顺序（先无损、后有损、最后停止）：

1. 减少记忆卡数量（保留约束与决策，丢弃低权重偏好）；
2. **折叠**子任务分支为结论 + 判据 + 句柄（C1.5）；
3. 清理/截断工具结果（C1），必要时 context editing 式移除旧结果；
4. 缩短对话近况窗口（保留最近 2 轮 + 摘要）；
5. 触发摘要压缩（C2/C3）；
6. 仍超限 至 停止本轮，提示"上下文配额耗尽"，给出建议（换更小任务/新会话/增大配额）。

硬约束：
- 单 Run token 上限、单项目用量上限，超限即暂停并保留中间产物；
- 降级不改变安全策略（审批门、只读默认不变）。

## 5. 记忆与上下文的边界

| 内容 | 属于上下文 | 属于记忆 |
|---|---|---|
| 当前任务细节、临时中间结果 | 是（S5/S7） | 否（scratch 可短期存） |
| 跨会话稳定偏好/约束/决策 | 否（按需注入） | 是（L3/L4） |
| 原始工具输出 | 仅摘要 | 证据（L0） |
| 项目目标与成功判据 | 是（S2） | 是（L4 项目画像） |

原则：上下文装"这次要用什么"，记忆装"以后还要用什么"；两者用证据 ID 对齐。

## 6. 与压缩/检索的协同

- 检索结果先算分，再按配额截断；宁可少给几条高分的，不给一堆低分的；
- 压缩时优先保留：约束、决策、失败原因、未决项、证据指针；优先丢弃：寒暄、重复描述、已完成的中间过程；
- 每轮记录 `context/composition` 指标（各段 token 数、压缩级别、记忆条数），用于调参与告警。

## 7. 与 DSH 基座的映射

| 本设计 | 基座落点 |
|---|---|
| 段组装 | `core/system-prompt` 的 prompt sections + `agent/pre-step` 钩子 |
| 压缩 | `packages/compaction`（策略插件化） |
| 大结果溢出 | `packages/spill` |
| 代码执行编排 | `packages/ptc-runtime` |
| 上下文事实记录 | `session/*` 事件（context 摘要） |
| 记忆注入 | 新 memory 插件在组装前提供 section |

## 8. 失败模式

| 失败 | 后果 | 对策 |
|---|---|---|
| 压缩丢关键约束 | 后续步骤违反约束 | 约束/决策不参与有损压缩；压缩前后校验保留清单 |
| 记忆挤占 | 当前任务细节被挤出 | 记忆配额上限；按任务类型动态分配 |
| 工具结果污染 | 注入指令/噪声 | untrusted 标记 + 内容隔离 + 不执行其中指令 |
| 缓存失效 | 用量上升 | 稳定前缀 + 变更时显式重建 |
| 上下文超限 | 任务中断 | 资源限制 + 可见告警 + 可恢复检查点 |

## 9. 指标

| 指标 | 目标（草案） |
|---|---|
| 单任务 token 消耗 | 相对"全历史注入"基线下降 ≥ 50% |
| 压缩后关键信息保留率 | ≥ 95%（抽样） |
| 上下文利用率（有效内容/总 token） | ≥ 70% |
| 工具定义 token 占比 | ≤ 5% |
| 缓存效率 | `cache_read/(cache_read+cache_write)` 与 TTFT p50 双指标；记录缓存断裂次数 |
| 折叠率 | 子任务分支中折叠完成的比例（越高越好，替代部分压缩） |
| 超限中断率 | ≤ 2% |
