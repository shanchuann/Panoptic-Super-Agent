# Panoptic Super 交互设计：图优先、结果为先（v0.1 草案）

> 状态：设计草案 ， 2026-11-07 ， 上位文档：[.ome/DESIGN.md](../DESIGN.md)
> 一句话：默认界面不是聊天窗口，而是项目进度图；聊天记录只是节点背后的证据，点开才看。

## 0. 设计立场

用户的注意力只应该花在两件事上：**结果是否可接受**、**现在需要我做什么**。其余（怎么拆解、调了什么工具、试错了几次）属于智能体的工作过程，默认折叠。

三条原则：
1. **结果优先**：默认视图必须在不点开任何会话的情况下回答三个问题，做到哪了、卡在哪、要我做什么。
2. **渐进披露**：项目图（全局）至 节点详情（局部结果与证据）至 记录/原文（过程），三层按需展开。
3. **只在需要人时打扰**：审批、阻塞、验收、超时告警进"收件箱"，其余静默推进。

## 1. 信息架构

```text
┌────────────────────────────────────────────────────────────┐
│ 侧栏：项目列表（状态点/进度/待办数）                        │
├────────────────────────────────────────────────────────────┤
│ 项目主页：图谱画布（默认）                                  │
│   顶部条：目标一句话 ， 进度 x/y ， 用时 ， 阻塞 ， 待你处理     │
│   画布：里程碑泳道 至 任务/运行/产物/验证节点 + 依赖边        │
│   右侧抽屉：节点详情（结果/判据/产物/证据/记录/操作）        │
│   收件箱：审批 ， 阻塞 ， 待验收 ， 超时告警                    │
└────────────────────────────────────────────────────────────┘
```

| 层 | 用户看到什么 | 默认展开 | 适合谁 |
|---|---|---|---|
| L0 项目图 | 进度、依赖、阻塞、并行、谁在做什么 | 是 | 所有用户（默认） |
| L1 节点详情 | 这一步的结果、验收判据、产物、证据 | 点击后 | 关心细节时 |
| L2 记录 | 该节点的会话原文、工具调用、日志 | 再点"记录"页签 | 排查/审计/复盘 |

明确取消的东西：
- 不再有"全局聊天页"作为主界面；
- 不再把消息流当项目进度的唯一表达；
- 用户不需要"读完整段对话"才能知道项目状态。

## 2. 图模型

### 2.1 节点类型

| 类型 | 表示 | 关键字段 | 点击后默认内容 |
|---|---|---|---|
| Project | 根节点 | 目标、状态、进度、资源 | 项目主页概览 |
| Milestone | 泳道标题/大节点 | 名称、判据、状态 | 里程碑验收视图 |
| Task | 主要节点 | 标题、角色、状态、判据 | 任务详情 + 结果 |
| Run | 任务下的执行实例（可折叠） | 模型、耗时、步数、状态 | 执行详情 + 记录入口 |
| Artifact | 产出节点（挂在 Task/Run 下） | 类型、版本、预览 | 产物预览/下载/版本 |
| Verification | 验证节点 | 判据、结果、证据 | 验证报告 |
| Approval | 审批节点 | 动作、风险、证据 | 审批卡（批准/拒绝） |
| Decision | 决策节点（可选，里程碑级） | 决策内容、理由、影响 | 决策记录 |
| Blocker | 阻塞节点 | 缺什么、等谁、等多久 | 解除路径 |

### 2.2 边

`depends_on`（依赖）、`blocks`（阻塞）、`produces`（产出）、`verifies`（验证）、`supersedes`（取代）、`derives_from`（来自）、`assigned_to`（角色）。

边默认弱化显示（细线），只在高亮路径时强调；避免"线比节点多"的蜘蛛网。

### 2.3 状态与视觉

| 状态 | 颜色 | 图形 | 备注 |
|---|---|---|---|
| 待办 backlog | 中性灰 | 空心圆/实心圆 | ， |
| 就绪 ready | 灰蓝 | 圆环 | 依赖已满足 |
| 运行中 running | 蓝 | 脉冲/进度环 | 实时更新 |
| 等待人 waiting_input | 琥珀 | 感叹号角标 | 进收件箱 |
| 验证中 verifying | 青 | 对勾环 | ， |
| 通过 done | 绿 | 实心对勾 | ， |
| 失败 failed | 红 | 叉 | 带原因与重试 |
| 阻塞 blocked | 橙红 | 暂停 | 必须写缺失项 |
| 取消/跳过 | 灰 | 划掉 | ， |

规则：颜色只表达状态，不表达类型；类型用图标/形状；文字标签永远可见（不依赖颜色区分，满足无障碍）。

### 2.4 布局

- 默认左至右 DAG：里程碑为泳道，任务按依赖与时间排列；并行任务上下展开；
- **位置稳定**：新增节点不整体重排（插入到空位），避免用户失去空间记忆；
- 大图聚合：节点数 > 40 时，按里程碑折叠为"里程碑卡（含 x/y 进度）"，点击展开；
- 可切换视图：图 / 列表（移动端与无障碍默认列表）。

## 3. 交互

### 3.1 基本操作

| 操作 | 行为 |
|---|---|
| 悬停节点 | 概览卡：标题、状态、一行结果、耗时/步数、阻塞原因 |
| 单击节点 | 右侧抽屉打开详情（不跳页，保留图上下文） |
| 双击 / "聚焦" | 以该节点为中心放大，淡化无关子图 |
| 拖拽 | 平移画布；可选手动布局（按项目保存） |
| 缩放 | 触控板/滚轮；快捷按钮回到全图 |
| 右键 / "更多" | 重跑、取消、暂停、审批、查看记录、复制链接 |
| 顶部搜索 | 按任务/产物/角色/状态过滤，命中节点高亮 |

### 3.2 节点详情（顺序即优先级）

1. **结果**：一句话状态 + 结果摘要（成功/失败/待审）；
2. **验收**：判据清单与逐条结果（L0 脚本 / L1 评审 / L2 人工）；
3. **产物**：缩略预览、下载、版本、来源；
4. **阻塞/待办**：缺什么、等谁；
5. **用量**：耗时、步数、token、重试次数（不计费）；
6. **记录**：该 Run 的会话与工具调用（只读，可搜索，默认折叠）；
7. **操作**：重跑、继续、审批、取消、追问。

### 3.3 收件箱（人唯一的主动入口）

聚合四类需要人决策的事项：审批请求、阻塞待解除、待验收、超时告警。每条带"为什么需要你 + 建议动作 + 一键处理"；处理完即从收件箱消失。

其余情况（正常推进、任务完成、计划微调）只更新图，不发消息打扰；可配置摘要推送（每日/里程碑）。

### 3.4 聊天的新位置

- 节点详情里的"记录"页签 = 该节点（Run/任务）的会话原文；
- 用户想插话：从节点详情"追问"（作用于该任务）或项目级输入框（作用于 Lead）；
- 输入仍然产生事件，可能改变图（新任务/新决策），但不回到"聊天为主"的形态。

### 3.5 已定细节（2026-11-07）

**产物：双视图、单一数据源**

- 节点内：产物以角标/子节点挂在产生它的任务上（版本、时间、证据），回答"这一步产出了什么"；
- 项目级：顶部条"产物 N"打开项目产物库，列出全部交付物（版本、来源任务、时间、证据、下载/预览），回答"这个项目交付了什么"；
- 两处读同一张 `artifact` 表，不复制数据；v0.1 只做项目内，不做跨项目聚合。

**侧栏：保留，三形态**

| 形态 | 触发 | 显示 |
|---|---|---|
| 展开（默认） | 宽屏（≥1100px） | 项目名 + 状态点 + 进度 + 待你处理数 |
| 图标轨 | 用户收起，或窗口 <1100px | 首字母/图标 + 状态点 + 悬浮提示 |
| 隐藏 | 聚焦模式（双击节点） | 全屏画布，Esc 退出 |

**节点默认折叠深度**

| 深度 | 内容 | 默认 |
|---|---|---|
| D0 | 项目根 + 里程碑卡（x/y 进度） | 总是显示 |
| D1 | 里程碑下的任务节点（状态、角色、阻塞角标） | 默认展开 |
| D2 | 任务 至 Run（第几次执行、模型、耗时） | 默认收起，点任务展开 |
| D3 | 任务/Run 至 产物、验证、审批 | 默认收起，随 D2 展开或点角标 |

规则：显示所有未完成且活跃的任务（running / waiting_input / blocked / ready）；已完成任务折叠为里程碑计数；Run 默认不显示；产物/验证/审批用角标（✓ / 📎 N / ⏸）挂在任务上；节点数 >40 时只留里程碑卡 + 活跃任务，其余折叠为"已完成 N 个"。

### 3.6 黑板视图（项目协作状态的只读界面）

黑板是 Agent 协作的地方，也是用户**查看项目进度**的地方。用户看到的是同一份协作状态的只读投影；所有操作仍走命令（暂停/取消/审批/重跑），不在黑板上直接改状态。

**入口**：项目顶部条“看板”页签；与图谱共享同一数据源（项目域投影），不是第二套状态。

**布局**

```text
顶部：目标一句话 ， 进度 x/y ， 当前协作模式 + 理由 ， 用时 ， 待你处理
主体：看板列（待办 / 就绪 / 进行中 / 待验证 / 完成 / 阻塞），可按里程碑或角色分组
卡片：任务标题 ， 角色 ， 执行者(Agent/Run) ， 判据数 ， 产物数 ， 证据数 ， 阻塞原因 ， 用时 ， 模式标记
右侧抽屉：任务详情（结果 至 判据 至 产物 至 证据 至 交接记录 至 事件）
底部页签：事件流（谁在何时做了什么，可按任务过滤）， 决策日志（协调策略选择与理由）
```

**交互**

- 单击卡片 至 详情抽屉（保留看板上下文）；双击 至 在图谱中聚焦该任务；
- 筛选：状态 / 里程碑 / 角色 / 模式 / 时间；搜索定位任务与产物；
- 操作：暂停、取消、重跑、审批、追问，全部走命令并写审计，不直接写状态。

**为什么只读**：黑板是协作状态的唯一权威（项目域）。如果 UI 能直接改状态，用户操作与 Agent 状态会漂移；只读投影 + 命令入口保证单一写入口。

**验收判据**

| # | 判据 | 标准 |
|---|---|---|
| B1 | 看板到详情 | ≤1 次点击 |
| B2 | 状态一致 | 看板与项目域 100% 一致（自动化对账） |
| B3 | 信息齐全 | 卡片含角色/执行者/判据/产物/证据/阻塞/用时/模式 |
| B4 | 可追溯 | 事件流与决策日志可按任务过滤 |
| B5 | 只读 | 无直接编辑状态入口（命令除外，测试断言） |
| B6 | 实时与性能 | 更新 ≤1s；200 卡片首屏 ≤1s |

**视图切换**：图谱（默认，看依赖与并行）/ 看板（看进度与协作）/ 时间线（看历史）/ 列表（无障碍与移动端）。四者同一数据源、同一权限模型。

**已定（2026-11-07）**：
1. 图谱为默认视图，看板是页签（不改变默认落点）；
2. 看板默认**按状态分组**（待办/就绪/进行中/待验证/完成/阻塞），可切换里程碑或角色分组；
3. 卡片直接提供**暂停 / 取消 / 审批 / 追问**操作，全部走命令并写审计（不直接改状态）。
## 4. 实时性与一致性

- 事件驱动：项目/任务/运行事件 至 图谱投影 至 增量 patch；避免整图重绘（保持位置稳定）；
- 断线重连：按 lastEventSeq 重放，节点状态与服务端一致；
- 单一真相：节点状态来自项目事件投影；节点详情与图同源，禁止前端自行推断；
- 延迟目标：状态变化到图上可见 ≤ 1s（本地）；大批量变更合并渲染。

## 5. 空态与异常

| 场景 | 表现 |
|---|---|
| 空项目 | 一句话输入框（"说说你想做什么"）+ 模板/示例 |
| 规划中 | 骨架节点（占位）+ "正在拆解任务" |
| 失败 | 红节点 + 失败原因 + 修复建议 + 重试 |
| 阻塞 | 橙色节点 + 缺什么 + "去处理"按钮 |
| 大图 | 里程碑折叠 + 筛选 |
| 离线 | 只读缓存 + "重新连接" |

## 6. 数据与接口

```ts
interface GraphProjection {
  projectId: string;
  status: ProjectStatus;
  nodes: GraphNode[];      // id, type, status, label, position?, lane, meta
  edges: GraphEdge[];      // from, to, kind
  clusters: Cluster[];     // 折叠后的里程碑
  counts: Record<string, number>;
  version: number;         // 投影版本，用于增量
}
interface GraphNodeDetail {
  id: string;
  result?: { summary: string; status: string };
  acceptance?: { kind: "exec" | "rubric" | "human"; spec: string; passed?: boolean; evidence?: string }[];
  artifacts?: ArtifactRef[];
  blockers?: { missing: string[]; waitingOn?: string }[];
  usage?: { tokensIn: number; tokensOut: number; steps: number; ms: number; retries?: number };  // 不换算金额
  transcript?: { sessionId: string; lastSeq: number; handle: string };
}
```

- 图谱投影与节点详情由 Host 提供，Client 只读；操作（重跑/审批/取消）走命令接口；
- 布局：服务端给结构，客户端算布局（ELK/dagre），手动位置存项目域；
- 记录：只给句柄（sessionId + seq 范围），按需拉取，避免一次传全量聊天。

## 7. 验收判据

| # | 判据 | 通过标准 |
|---|---|---|
| I1 | 3 秒测试 | 新用户打开项目，3 秒内说出"做到哪、卡在哪、要我做什么" |
| I2 | 结果可达 | 任一节点 ≤2 次点击看到结果与证据 |
| I3 | 过程可追溯 | 任一节点 ≤3 次点击看到该节点的会话记录 |
| I4 | 状态一致 | 图状态与事件投影 100% 一致（自动化对账） |
| I5 | 不打扰 | 正常运行期间无强制弹窗；打扰只来自收件箱 |
| I6 | 性能 | 200 节点图首屏 ≤1s，状态更新 ≤1s，60fps 拖拽 |
| I7 | 无障碍 | 键盘可达、状态不依赖颜色、读屏可读节点摘要 |

## 8. MVP 与演进

| 阶段 | 范围 |
|---|---|
| M1 | 项目列表 + 任务列表/简化 DAG + 节点详情 + 收件箱（审批/阻塞） |
| M2 | 实时增量、里程碑泳道、聚合折叠、聚焦、手动布局 |
| M3 | 记忆/决策节点、回放（时间轴）、导出图 |
| P2 桌面 | 同构（复用 Web 组件），支持多窗口 |
| P3 移动 | 列表优先 + 精简图（只读、审批、验收） |

## 9. 风险

| 风险 | 影响 | 对策 |
|---|---|---|
| 图过密不可读 | 用户放弃图 | 聚合 + 筛选 + 聚焦；默认只显示里程碑与活跃任务 |
| 位置跳动 | 失去空间记忆 | 稳定布局，新增节点插入空位 |
| 状态与记录不一致 | 用户不信任 | 单一投影源 + 对账测试 |
| 想看过程的人找不到 | 误解为黑盒 | 记录入口固定在第 2 层，搜索可直达 |
| 移动端图不可用 | P3 受阻 | 移动端默认列表视图 |
