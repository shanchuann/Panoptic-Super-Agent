# 事件驱动运行时：从“用户触发”到“环境触发”

> 状态：设计草案 ， 2026-11-07 ， 上位：[.ome/DESIGN.md](../DESIGN.md)、[ADR-0009](../../docs/adr/ADR-0009-event-driven-runtime.md)
> 一句话：把项目事件、IM、GitHub、CI、定时任务变成触发器；Router 做分诊，Worker 做执行；外部 Watchdog 盯住跑偏；远程运行时先留接口。

## 0. 目标场景

“有人在群里/PR 里提出问题，智能体自己修、自己测、自己推送”，这是事件驱动 + 全双工 + 看门狗的组合，而不是一个更长的 loop。

## 1. Super-agent 六特性与我们的映射

| Super-agent 特性 | 它解决什么 | 我们的落点 | 采纳状态 |
|---|---|---|---|
| 双层架构（Router + Worker） | 用户只面对一个入口，Router 分诊、Worker 执行 | 协调策略层 + Lead（Router 角色）至 Run/Subagent（Worker） | **采纳**（Router 用规则 + 轻模型） |
| 事件驱动（Trigger） | 从被动等指令到主动响应 | 项目事件 + 触发器服务（IM/GitHub/CI/定时/Webhook） | **P1.5 采纳** |
| 订阅与直通 | 后续相关事件直达 Worker，减少 Router 重复判断 | 订阅注册表（PR/话题/项目）至 直达对应 Run | **P1.5 采纳** |
| 全双工 | 派活不阻塞对话；可随时插话/叫停 | 异步 Run + 收件箱 + 中断/暂停 | **P1 采纳**（已有异步 Run） |
| 存算分离 | 关闭本机仍在线、换机执行 | 远程运行时 adapter（云端会话 + 本地执行器） | **预留，P2 再评估** |
| Watchdog | 自动发现死循环/跑偏 | guard 插件 + 外部 watchdog 服务（心跳/无进展/方向偏移） | **P1.5 采纳**（先进程内，后独立） |

## 2. 触发器（Trigger）

~~~text
来源：项目事件 / IM 群消息 / GitHub issue，PR，comment / CI 失败 / 定时 / Webhook
  至 规则层过滤（来源白名单、签名、去重、限流、路由键）
  至 模型分诊（是否要执行、属于哪个项目/任务、优先级）
  至 Router 派发（绑定 playbook + 预算 + 审批策略）
  至 Run 执行；结果回写项目域与来源渠道
~~~

规则：
1. **来源不可信**：外部触发器默认 untrusted，必须签名/白名单/限流；不可信内容不驱动高危工具；
2. **规则先行**：能用规则过滤的不用模型；模型只做"是否执行/归属"判断；
3. **预算与审批**：每个触发器带预算与审批策略；"自己推送"属于外发动作，必须审批或显式授权；
4. **可追溯**：触发器 id、来源、判定、派发、结果全链路记录。

## 3. 订阅与直通

- Worker 完成派发后可**订阅**后续相关事件（同一 PR 的评论、同一话题的回复、同一失败的重试）；
- 后续事件直达该 Worker，不再经过 Router 全量判断（减少重复推理）；
- 订阅有过期时间与取消条件；项目结束/任务完成自动退订；
- 直通不等于绕过治理：审批、预算、写域仍生效。

## 4. 全双工

- Run 异步执行，前台对话不阻塞；用户可随时插话、暂停、取消、追加要求；
- 收件箱承接需要人的事件；长任务有 checkpoint，可恢复；
- 同一项目的写操作仍单线程（写域互斥），读操作可并行。

## 5. Watchdog

| 检查 | 信号 | 动作 |
|---|---|---|
| 心跳 | Run 超时无事件 | 暂停 + 告警 + 尝试恢复 |
| 死循环 | 重复工具调用/重复步骤 | 中断 + 重规划/转人工 |
| 无进展 | 连续 N 步无新证据/无产物 | 暂停 + 升级 |
| 方向偏移 | 与 Brief/判据偏离（模型评审） | 暂停 + 要求确认 |
| 预算/资源 | 步数/时长接近上限 | 提前告警 + 降级 |

- P1 先做进程内 watchdog（guard 插件）；
- P1.5 起独立 watchdog 服务（外部视角，防止被监控进程本身失效）；
- Watchdog 只能暂停/升级/告警，不能替代审批与验收。

## 6. 远程运行时（预留）

- 目标：会话/记忆/项目状态在云端，执行器在本地或远程机器；关闭本机仍可调度；
- 形态：Host 服务 + 远程执行器 adapter（RPC/WebSocket），复用同一套审批/审计/预算；
- 约束：密钥只在执行端、传输加密、设备配对与撤销；远程执行默认关闭；
- 阶段：P2 评估，不阻塞 P1。

## 7. 与 oh-my-software-engineering 的关系

事件触发只负责“什么时候开始”，不改变“怎么干”：任务仍按任务卡、验证器、写域、证据与门禁执行；自动修复/测试/推送同样要过 P3/P4 门禁。

## 8. 验收判据

| # | 判据 | 标准 |
|---|---|---|
| R1 | 触发器 | 5 类来源可接入；规则过滤命中率与误报可测 |
| R2 | 分诊 | 归属项目/任务的判断准确率 ≥85%（20 条样本） |
| R3 | 直通 | 订阅事件直达率 ≥90%，Router 调用减少 ≥30% |
| R4 | 全双工 | 长任务执行中可插话/暂停/取消（端到端用例） |
| R5 | Watchdog | 死循环/无进展/超时各 1 个用例被正确拦截 |
| R6 | 安全 | 未签名/非白名单触发器被拒绝；推送动作经审批 |
