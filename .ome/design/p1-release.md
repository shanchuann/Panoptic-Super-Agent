# P1 发布定义：薄而完整

> 状态：设计草案 ， 2026-11-07 ， 上位：[.ome/DESIGN.md](../DESIGN.md)、[SCOPE.md](../SCOPE.md)
> 一句话：**完整度不是功能数量，而是一条窄旅程没有断点**，每个 P1 功能六态齐全、数据可导出可删除、交付物可安装可回滚。

## 0. 完整度的定义

| 看起来"完整" | 实际"完整" |
|---|---|
| 功能列表很长 | 一条用户旅程从头到尾能走通，且每一步都有失败处理 |
| 每个功能都能演示 | 每个功能有 空/加载/错误/成功/无权限/离线 六态 + 文档 + 测试 |
| 数据能存 | 能导出、能导入、能删除、能备份、能迁移 |
| 能跑 | 能安装、能升级、能回滚、能诊断 |
| 覆盖面广 | 覆盖一个真实用户的一段真实工作，而不是所有人的一个切片 |

**P1 的策略：范围收窄、闭环做深。** 宁可一条窄旅程 100% 可用，不要十条旅程 40% 可用。

## 1. P1 唯一旅程（Definition of Journey）

~~~text
安装 至 首次启动（BYOK 配置 + 连通性测试）
  至 新建项目（一句话目标）
  至 问询（确认目标/判据/排除/参考）
  至 计划（任务图 + 预计时长）
  至 执行（单 agent + 单次交接；图/看板可见）
  至 验证（L0 脚本 + L1 评审 + L2 人工）
  至 交付（产物 + 来源 + 版本）
  至 迭代（继承 + 差异执行）
  至 导出 / 删除 / 备份
~~~

每一步都必须定义：入口、成功态、失败态、恢复方式、用户可见提示。

恢复属于旅程的一部分。用户关闭程序后重新打开，系统应能恢复活动任务，说明已经完成的工作、尚未完成的事项与证据位置，并且不重复执行已提交的写操作。未列入本旅程的模块只实现最小接口。

## 2. P1 必须有的（薄而完整）

| 模块 | P1 最小形态 | 不做的部分（P2+） |
|---|---|---|
| 项目域 | 项目/任务/Run/产物/审计；状态机；导出/删除 | 多级层级、项目模板市场 |
| 问询 | Brief/Spec/排除/判据；一次确认；快速/深挖模式 | 无限追问、AI 自动补全 spec |
| 计划 | 任务 DAG + 预计时长 + 人工可改 | 自动重规划策略库 |
| 执行 | 单 agent + 单次交接；并发 ≤3；写域互斥 | 多级扇出、辩论、领取/租约 |
| 交互 | 图谱（默认）+ 看板（页签）+ 收件箱 + 节点详情 | 时间线视图、手动布局、移动端 |
| 记忆 | MM1：L0/L2 + 显式读写删 + 标签 + 关闭开关 | 权重衰减、睡眠整合、L3 资产化 |
| 网关 | BYOK（地址/密钥/协议/三档）+ 连通性测试 + 降级 | 内置供应商、多模态编解码 |
| 沙箱 | 本地隔离（文件/网络限制） | 云沙箱、远程执行 |
| 治理 | 默认只读、三类审批、资源上限、审计 | 企业 RBAC、多租户 |
| 引导 | 首次启动向导、示例项目、帮助入口 | 教程视频、社区 |
| 数据 | 导出/导入/删除/备份 | 跨设备同步、云备份 |
| 交付物 | 安装/启动脚本、README、配置示例、LICENSE/第三方、版本号、变更日志 | 自动更新、签名安装包（P2） |

**P1 明确不做**：五层记忆的权重/睡眠、黑板视图/时间线、事件驱动运行时/Watchdog、六类范式（只做 research/code 两类）、多级扇出/辩论、远程控制/GUI、A2A、移动端、音频多模态。

## 3. 六态覆盖（每个 P1 功能都必须有）

| 状态 | 要求 | 反例 |
|---|---|---|
| 空态 | 首次进入有引导，不是空白页 | 项目列表空白无提示 |
| 加载态 | 有进度/骨架屏/可取消 | 点任务后卡住无反馈 |
| 错误态 | 说明原因 + 可操作建议 | "出错了" |
| 成功态 | 结果 + 证据 + 下一步 | 只显示"完成" |
| 无权限/需审批 | 说明为什么、怎么处理 | 静默失败 |
| 离线/资源超限 | 明确状态 + 恢复路径 | 一直转圈 |

七个核心界面（项目列表、问询、计划、图谱、看板、节点详情、收件箱）逐一验收六态。

## 4. 数据闭环

- 创建 至 使用 至 导出（Brief/计划/任务/产物/记忆/审计）至 导入（新设备/新后端）至 删除（级联）至 备份/恢复；
- 每个域有 schema 版本 + 迁移函数；迁移可 dry-run；
- 删除后 60 秒内检索/列表/详情均不可见（测试）。

## 5. 异常闭环（至少覆盖）

| 异常 | 用户看到 | 系统行为 |
|---|---|---|
| 模型不可用/密钥失效 | 原因 + 去设置 | 降级/暂停，不丢状态 |
| 沙箱启动失败 | 原因 + 重试 | 保留 checkpoint |
| 审批被拒 | 决策记录 + 替代方案 | 任务 blocked |
| 资源超限 | 用量 + 选项 | limit_stopped + 可续跑 |
| 运行中断/崩溃 | 恢复提示 | 从事件日志恢复 |
| 磁盘满/写入失败 | 原因 + 清理建议 | 不静默丢产物 |
| 升级失败 | 回滚说明 | 保留旧版本 |

## 6. 交付物清单（发布前必须齐）

1. 安装/启动：一条命令或安装包（P1 Web 本机启动）；
2. 文档：README、快速开始、BYOK 配置、常见问题、数据位置与删除；
3. 配置示例：最小配置、三档模型示例、沙箱配置；
4. 示例项目：一个可跑通的样例（研究至文档）；
5. 许可证与第三方通告：LICENSE、NOTICE、THIRD_PARTY_NOTICES；
6. 版本与变更日志：版本号、CHANGELOG、升级说明；
7. 回滚说明：保留旧版本与数据快照的方法；
8. 诊断：日志位置、导出诊断包（不含密钥）。

## 7. 质量门槛（P1 发布判据）

| 项 | 门槛 |
|---|---|
| 用户旅程 | 唯一旅程 100% 可走通，无死路 |
| 六态 | 七个核心界面六态齐全（走查表） |
| 数据 | 导出至导入至删除 往返测试通过 |
| 异常 | 7 类异常用例通过 |
| 交付物 | 清单 8 项齐全 |
| 性能 | 首屏 ≤2s；图谱 200 节点 ≤1s；操作反馈 ≤1s |
| 可用性 | 3 秒测试：新用户说出"做到哪/卡在哪/要我做什么" |
| 无障碍 | 键盘可达、状态不只靠颜色 |
| 安全 | 密钥不外泄；5 类攻击用例全拦截 |
| 恢复 | 崩溃前后各一次，恢复后不重复已提交副作用，并说明已完成与下一步 |
| 账本 | 有副作用工具调用均有执行记录与幂等键 |

## 8. 范围取舍规则

新增任何功能进 P1，必须同时满足：

1. 属于唯一旅程的必经步骤；
2. 六态 + 文档 + 测试 + 证据齐全；
3. 不引入新的顶层概念（否则先进"概念宪法"评审）；
4. 能从 P1 移除时不影响旅程走通。

否则进 P2，不占 P1 带宽。
