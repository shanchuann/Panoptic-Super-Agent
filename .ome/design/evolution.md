# Panoptic Super 演进方向：从单 Lead 到自适应协作（v0.1 草案）

> 状态：设计草案 ， 2026-11-07 ， 决策人：用户 ， 上位：[.ome/DESIGN.md](../DESIGN.md)、[ADR-0006](../../docs/adr/ADR-0006-collaboration-model.md)
> 一句话：用户始终只有一个窗口；协作方式按任务规模自适应；上下文从"继承历史"改成"按需拉取"。

## 0. 为什么现在的协作会落后

P1 前的基线形态是"单 Lead + 受控 subagent"（ADR-0006 已确认演进方向）：Lead 既做上下文中枢，又做串行路由器，还做决策者。小任务够用，项目一大就暴露三个瓶颈：

1. **上下文中枢**：所有信息必须经过 Lead，窗口迟早被塞满；
2. **串行路由**：Lead 逐个派活，天然串行，长任务排队；
3. **单点决策**：Lead 的判断同时决定分工与验收，出错没有第二视角。

结论：不是"Lead 分派"本身错，而是 Lead 不该同时承担这三个职责。演进方向是把三者拆开：**协作状态放黑板、上下文按需拉取、Lead 降级为仲裁者**。

## 1. 三条演进主轴

| 主轴 | 从 | 到 |
|---|---|---|
| 协作 | 固定拓扑（Lead至Worker） | 自适应拓扑（solo / 编排 / 黑板 / 流水线 / 层级 / 辩论） |
| 上下文 | 继承完整历史 | 上下文包（任务 + 产物 + 记忆 + 事件，配额内按需拉取） |
| 交互 | 聊天流 | 图/结果优先 + 单窗口投影（已定，见 [interaction.md](interaction.md)） |

## 2. 协作范式菜单

| 模式 | 形态 | 适合 | 主要代价 |
|---|---|---|---|
| M0 solo | 单 Agent 直接执行 | 单产物、少步骤、单一领域 | 长任务会爆上下文 |
| M1 orchestrator | Lead 派活 + 单次交接（当前） | 中等任务、需要集中判断 | Lead 串行与上下文中枢 |
| M2 blackboard | 项目域状态模型 + 均匀扇出调度（领取/租约 P2，仅均匀批次） | 多独立子任务、长项目 | 需要协议、冲突与可见性 |
| M3 pipeline | 固定阶段链（研究至实现至验证） | SOP 明确的重复流程 | 灵活性低 |
| M4 两级扇出 | 最多两级，不设子 Lead | 超大项目、跨领域 | 层级信息损耗 |
| M5 debate | 仅离线复核/人工工具，不进运行时 | 高风险判断、证据冲突 | 约 2–3× 用量、有"由对转错"实证 |
| M6 human | 升级给人决策 | 不可逆、合规、价值判断 | 人成为瓶颈 |

## 3. 拓扑选择：协调策略层

新增一层（Host 侧插件，不是 Agent）：

```text
信号（产物数/可分解性/预估步数/领域广度/判据清晰度/风险/写域冲突/资源）
  至 规则打分 至 边界带才调小模型 至 结构化决策 {mode, contextStrategy, parallelism, rationale}
  至 写项目域审计 至 调度器按 mode 执行
```

- **规则优先**：确定性、可单测、开销可忽略；模型只在模糊区间用；
- **默认策略：最小充分范式 + 按证据升级**（用户 2026-11-07 确认）；
- **人工覆盖**：项目级可强制模式，写入审计；
- **迟滞**：同一信号持续或超阈值才切换；只在项目启动、里程碑、阻塞事件重评估；
- **D9 门槛**：任何 M2 及以上拓扑必须先有自家 pass^k A/B 证据才能进默认路径；无证据保持 M0/M1；
- **升级前先试更便宜的路径**：压缩、子任务隔离、拆句柄；升级判据增加"未言明决策数"（子任务共享假设超阈值才禁止并行）。

### 升级触发（草案）

| 触发 | 升级到 |
|---|---|
| 上下文占用 >70%（必要非充分）或同一步失败 2 次 | solo 至 orchestrator |
| 独立子任务 ≥3 且写域不冲突 | orchestrator 至 blackboard |
| 阶段固定且顺序明确 | pipeline |
| 里程碑 >5 / 跨领域 | hierarchy |
| 高风险且证据冲突 | debate（仅离线复核） |
| 不可逆 / 合规 | human（强制） |

## 4. 上下文演进：从继承到按需

三层上下文分离：

| 层 | 装什么 | 谁读 | 大小控制 |
|---|---|---|---|
| 对话面 | 目标、决策、结果、待办 | 用户窗口 | 摘要投影，最小 |
| 协作面 | 任务 DAG、产物、证据、审批、事件 | 调度器与 Worker | 外部存储，不进对话 |
| 执行面 | 单任务上下文包 | 当前 Worker | 配额化、可解释、可复现 |

**上下文包（Context Packet）**：由 Context Broker 按任务生成，任务说明 + 相关产物 + 记忆检索结果 + 最近事件，带配额上限与来源标注；Worker 不继承别人的历史。

## 5. 演进路线

| 阶段 | 协作 | 上下文 | 验收 |
|---|---|---|---|
| P1（当前） | M0/M1 + 规则选择器 + 黑板（项目域已定）+ 黑板视图（只读看板） | 上下文包 + 对话面投影 | 路由与人工标注一致 ≥75%；决策开销 ≤2%；上下文包 ≤ 配额 |
| P1.5 | + M2 任务领取/租约 + 并行 Worker + 验证网络 | Broker 支持按需下钻 | 并行度、冲突率、交接信息丢失率 |
| P2 | + M3 pipeline、M4 层级（按项目规模）；M5 辩论可选 | 多级摘要与跨项目记忆共享 | 同任务 pass^k 对比；模式切换回滚 |
| P3 | A2A 对外适配（内部拓扑不变） | 跨设备上下文 | 互通与安全审计 |

## 6. 风险与反模式

| 风险 | 表现 | 防护 |
|---|---|---|
| 过度拆分 | 小任务开多 Agent，协调成本大于执行 | 最小充分范式 + 拆分下限 + 误升级率指标 |
| 拆分不足 | 单 Agent 爆上下文/串行太慢 | 上下文占用与失败次数触发升级 |
| 拓扑抖动 | 反复切换 | 迟滞 + 只在边界点重评估 + 切换需 checkpoint |
| 选择器烧钱 | 每次决策都调模型 | 规则优先，模型只在边界带 |
| 黑板变垃圾场 | 无人清理的状态与产物 | 单一写入口 + 审计 + 归档/删除 |
| 上下文包过载 | 包本身塞满窗口 | 配额化 + 句柄下钻 + 优先级排序 |

## 7. 验收指标

| 指标 | 目标（草案） |
|---|---|
| 路由准确率（与人工标注一致） | ≥75%（P1） |
| 误升级率（小任务被并行化） | ≤10% |
| 决策开销 | 规则版 P95 <10ms；如启用边界带小模型，P95 ≤ 任务时长 2% |
| 上下文包大小 | ≤ 配额上限；超限自动裁剪并记录 |
| 交接信息丢失率 | ≤5%（判据/证据/产物齐全） |
| 模式与执行一致率 | 100%（调度器只认决策对象） |
| 有/无自适应协作的 pass^k 差 | 目标 ≥+10pp（P2 验证） |

## 8. 待确认的演进决策

1. M2（黑板 + 领取）放在 P1.5 还是 P2？，建议 P1.5；
2. 辩论模式 M5 默认关闭、仅在项目设置开启，确认；
3. 协调策略层是否允许模型判断边界带，建议允许但可关闭；
4. 模式切换是否允许在任务中途（需 checkpoint），建议只允许在里程碑/阻塞点；
5. 是否把"模式 + 理由"展示给用户，建议展示在节点详情（可解释性优先）。
