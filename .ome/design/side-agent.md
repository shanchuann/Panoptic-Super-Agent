# 旁路智能体

状态：设计草案，2026-11-08。上位文档为 [DESIGN.md](../DESIGN.md)、[ADR-0011](../../docs/adr/ADR-0011-side-agent.md)。

## 1. 要解决的问题

主任务推进时，用户经常有临时问题。例如主 Agent 正在改代码，用户想问“这个函数为什么这样写”，或者“换一种方案会不会更简单”。如果直接发到主会话，会打断主 Agent 的下一步，改变主线上下文，消息还会顶到时间线顶部，把用户正在看的位置冲掉。

旁路智能体提供一条只读的侧通道。它共享当前主会话的上下文，用户可以提问并收到回复，但旁路消息不进入主线时间线，不改变主线滚动位置，也不作为主 Agent 下一轮输入。

## 2. 目标与非目标

目标：

1. 用户在主线任务运行时可以旁路提问，不打断主线执行。
2. 旁路回复基于主会话快照与项目状态，能回答“当前上下文里”的问题。
3. 旁路消息与主线消息物理分离，主 Agent 默认不可见。
4. 旁路面板有独立的未读标记与滚动位置，不影响主线。
5. 用户可以把一条旁路内容显式带入主线，带入前需要确认，带入后带来源。

非目标：

1. 旁路智能体不是第二个主 Agent，不接管任务，不执行写操作。
2. 旁路消息不默认写入长期记忆，也不默认写项目域。
3. 第一阶段不做多人共享旁路线程。
4. 第一阶段不做旁路智能体主动发言或定时巡检。

## 3. 使用场景

场景一。主 Agent 正在执行一个长任务。用户想确认某个判据的含义，在侧栏提问“验收判据里的回滚点指什么”。旁路回复后，主 Agent 继续执行，主线没有新消息。

场景二。用户想比较两个方案。旁路里让智能体列出 A 与 B 的差异，看完后决定不采纳，关闭旁路线程，主线不受影响。

场景三。旁路里发现一个关键约束，用户点击“带入主线”，确认后主线出现一条带来源的注记，主 Agent 下一轮可以看到它。

场景四。用户想回到昨天的旁路记录，打开侧栏的历史线程，继续追问。

## 4. 与主会话的关系

主线与旁路线程共用项目状态，但记录分开。

| 对象 | 主线 | 旁路线程 |
|---|---|---|
| 会话记录 | 主会话事件日志，只追加 | 独立的旁路记录，只追加 |
| 上下文 | 主 Agent 的上下文包 | 基于主会话快照生成的旁路上下文包 |
| 未读 | 主线未读 | 侧栏独立未读 |
| 滚动 | 主线位置保持不变 | 侧栏独立滚动 |
| 工具 | 按能力授权执行 | 默认只读白名单 |
| 记忆 | 正常写入 | 默认不写入，带入主线后才进入候选 |

主 Agent 的上下文装配器必须显式排除旁路记录。旁路记录不能写入主会话事件日志，否则会进入模型请求，违背隔离目标。

## 5. 上下文共享

旁路线程打开时生成一次主会话快照，包含：

- 项目标识、任务标识与当前状态；
- 目标、验收判据、约束与已确认决策；
- 稳定的系统前缀与工具目录摘要；
- 最近若干条主会话事件的可读摘要；
- 相关产物句柄与证据引用；
- 当前主 Agent 是否在运行。

快照带版本号与生成时间。旁路回复必须引用快照版本，便于解释“当时看到的是什么”。

第一阶段采用快照模式，打开后不再跟随主线新增事件。P1.5 提供跟随模式，主会话新增事件以摘要形式单向同步到旁路，仍不允许旁路反向写入主线。

上下文预算独立计算，不占用主会话配额。旁路超预算时按判据、约束、决策、任务状态、近期事件的顺序裁剪。

## 6. 数据模型

| 实体 | 字段 | 说明 |
|---|---|---|
| SideThread | id，projectId，mainSessionId，baseEventSeq，snapshotVersion，title，status，createdAt，archivedAt | 一个旁路线程 |
| SideMessage | id，threadId，role，content，seq，sourceEventSeqs，createdAt，promotedAt | 旁路消息 |
| SideSnapshot | id，threadId，version，payload，createdAt | 上下文快照 |
| SidePromotion | id，threadId，messageId，targetSessionId，note，confirmedBy，createdAt | 带入主线的记录 |

状态：线程为打开、空闲、归档。消息为正常、已带入、已删除。带入记录为待确认、已确认、已取消。

旁路记录存放在项目存储域的独立表，不写入主会话事件日志。旁路事件只用于审计与恢复，不进入主模型请求。

## 7. 接口

服务方法：

- createThread：创建旁路线程，生成快照。
- ask：提交用户问题，运行旁路智能体，写入旁路消息。
- archiveThread：归档线程。
- promote：请求带入主线，返回待确认记录。
- confirmPromotion：确认带入，写入主线注记与审计。
- listThreads：按项目与会话列出历史线程。

运行约束：

- ask 只允许只读工具，工具白名单由项目配置。
- 旁路运行有独立的步数与时长上限，默认小于主运行。
- 旁路运行不触发审批；需要审批的动作只能生成建议，由用户带入主线后执行。
- 主会话结束时，旁路线程可以继续存在，但快照标记为主会话已结束，回复需提示上下文可能过期。

契约细节见 [contracts/side-agent.md](../contracts/side-agent.md)。

## 8. 交互

侧栏从右侧滑出，宽度约为窗口的三分之一，主内容区宽度不变。侧栏默认收起，通过工具栏按钮或快捷键打开。

侧栏顶部显示旁路线程标题、快照时间与“带入主线”入口。消息列表紧凑排列，用户消息与旁路回复靠左，系统提示用浅色块。输入框在底部，支持多行与发送快捷键。

主线的滚动位置、未读计数与消息顺序不受侧栏影响。侧栏自己的未读标记显示在按钮上，不进入主线未读。

“带入主线”需要二次确认，预览将要写入的注记，确认后主线出现一条带旁路来源与快照版本的注记。带入不复制整段对话，只复制用户选中的内容与必要上下文。

## 9. 权限与安全

旁路默认只读。文件读取限制在当前项目工作区，网络访问默认关闭。旁路不能写文件、执行命令、提交代码、发送消息或付款。

旁路看到的内容与主会话相同等级，受项目隔离约束。旁路不能读取其他项目或其他用户的旁路线程。

带入主线是唯一写入路径。带入内容经过用户确认，写入审计，来源可追溯。带入不改变已有主线消息，只追加注记。

旁路记录中的敏感内容按项目敏感级处理，删除线程时级联删除消息与快照。

## 10. 失败与恢复

| 情况 | 行为 |
|---|---|
| 旁路智能体不可用 | 提示稍后重试，不影响主线 |
| 快照生成失败 | 允许以最小上下文打开，标记快照缺失 |
| 主会话已结束 | 允许继续提问，提示上下文可能过期 |
| 带入时主会话已切换 | 拒绝带入，提示选择目标会话 |
| 旁路线程过长 | 提示新建线程，旧线程可归档 |
| 存储写入失败 | 旁路消息不落库，提示重试，不阻塞主线 |

## 11. 验收判据

1. 旁路消息不出现在主线时间线，不改变主线未读与滚动位置。
2. 主 Agent 下一轮上下文不包含旁路消息，测试可证。
3. 旁路回复能引用当前任务、判据与决策，快照版本可追溯。
4. 旁路工具调用只出现只读工具，写操作被拒绝。
5. 带入主线需要确认，确认后主线出现带来源的注记。
6. 旁路线程按项目隔离，跨项目读取失败。
7. 删除线程后消息与快照不可检索。
8. 主会话结束时旁路仍可用，并提示上下文可能过期。
9. 旁路运行不占用主会话配额，超限时独立停止。
10. 旁路记录不写入主会话事件日志，审计可查。

## 12. 第一阶段范围

第一阶段实现：快照上下文、只读工具、侧栏交互、线程归档、带入主线、删除级联。

P1.5 再评估：跟随模式、旁路引用产物、旁路多线程并行、旁路建议转任务。

暂不做：旁路写操作、旁路审批、多人共享、跨设备同步。
