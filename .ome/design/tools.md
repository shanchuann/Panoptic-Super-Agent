# Panoptic Super 工具调用系统设计（v0.1 草案）

> 状态：设计草案 ， 2026-11-07 ， 上位文档：[.ome/DESIGN.md](../DESIGN.md)
> 一句话：所有"手脚"收敛到一个 `execute(name, input) 至 result` 入口；工具是权限边界，不是函数列表。

## 0. 设计原则

1. **统一入口**：内置工具、MCP 工具、代码执行、子智能体都表现为同一个执行契约；
2. **最小权限**：每个工具声明读写范围、网络范围、可逆性，默认只读；
3. **结果可控**：工具结果先归一化、脱敏、压缩，再进上下文（见 [context.md](context.md)）；
4. **可审计**：每次调用落 `tool/call`、`tool/result` 事件，含参数哈希、耗时、结果摘要；
5. **不可信隔离**：外部内容（网页/文档/第三方 MCP 返回）默认 `untrusted`，不能直接驱动高危动作；
6. **发现按需**：工具目录不全量注入，用检索按需提供 schema，避免固定 token 税。

## 1. 工具注册表

每条工具注册项（声明式，可在插件中注册）：

```ts
interface ToolSpec {
  name: string;                    // 全局唯一，例如 fs.write
  description: string;             // 给模型看的用途说明（短、动词开头）
  inputSchema: JSONSchema;         // 参数校验（模型/调用方边界）
  outputSchema?: JSONSchema;
  risk: "read" | "write" | "irreversible";   // 决定审批与沙箱
  approval?: "never" | "confirm" | "always"; // 覆盖默认策略
  idempotent: boolean;             // 影响重试
  timeoutMs: number;
  usageHint?: { tokens?: number; latencyMs?: number };  // 不换算金额
  sandbox?: "none" | "workspace" | "process"; // 执行环境要求
  trustOutput: "trusted" | "untrusted";
  scopes?: ("user" | "project" | "session")[]; // 可用作用域
}
```

## 2. 工具分类

| 类别 | 例子 | 权限要点 |
|---|---|---|
| 文件 | `fs.read` / `fs.write` / `fs.list` | 写操作限制在项目工作区；路径穿越校验 |
| 执行 | `shell.exec` / `sandbox.exec` | 进程隔离、无凭证、网络默认拒绝 |
| 检索 | `web.search` / `web.fetch` | 出站白名单；返回 untrusted |
| 代码编排 | `ptc.exec`（代码执行 + 工具调用） | 沙箱内运行，中间结果不回上下文 |
| 记忆 | `memory.search` / `memory.evidence` / `memory.remember` | 见 memory.md；写与删除需确认 |
| 项目 | `project.plan` / `task.assign` / `artifact.publish` | 状态迁移受状态机约束 |
| 交互 | `ask_user` / `approval.request` | 只读询问，不越权 |
| MCP | 外部 server 暴露的工具 | 第三方默认不可信；显式授权 |
| 子智能体 | `subagent.spawn` / `subagent.wait` | 只回摘要；资源上限与并发 |

## 3. 执行管线

```text
模型提出 tool/call（name + input）
 至 参数校验（JSON Schema；失败即返回结构化错误，不执行）
 至 策略判定：allow / deny / require-approval
      ， 作用域（项目/用户）， 风险等级 ， 白名单 ， 资源上限
 至 审批（如需）：挂起 至 用户决定 至 继续或终止
 至 沙箱/执行器执行（超时、并发限制、取消传播）
 至 结果归一化：结构化、脱敏、截断/溢出落盘、打 trust 标记
 至 落事件（tool/call、tool/result：参数哈希、耗时、结果摘要、证据指针）
 至 返回给模型：摘要 + 句柄（不放原始大结果）
```

规则：
- 参数校验在模型与工具之间做一次，失败返回可纠正的错误信息；
- 审批挂起不阻塞其他任务；被拒动作记录 `approval/decided`；
- 超时/取消必须传播到子进程与沙箱；
- 非幂等工具禁止自动重试。

## 4. 权限与审批

权限模型采用能力授权。授权对象为使用者、执行体或单次运行，授权范围包括项目、能力、资源路径或域名、有效期、调用次数与字节上限。

| 场景 | 策略 |
|---|---|
| 项目工作区内、已授权范围的读 | 允许 |
| 项目工作区内、已授权范围的写 | 允许，连续执行不打断 |
| 越界写、删除、覆盖关键文件 | 审批 |
| 付款、对外发送、发布 | 审批 |
| 不可信内容驱动的高危操作 | 拒绝或强制人工确认 |

权限判断在可信代码中完成，模型不能自行授权。审批绑定动作与参数哈希，参数变化后原审批失效。契约见 [capability-approval.md](../contracts/capability-approval.md)。

补充规则：
- 工具白名单：项目可限制可用工具集合；
- 每工具最小权限：例如 `web.fetch` 不允许访问内网地址（SSRF 防护）；
- 凭证不入沙箱：工具代理注入，不把密钥写进工作区；
- 不可信内容不得直接驱动 `irreversible` 工具：需要人确认或经过二次校验。

## 5. 工具发现（Tool Search）

- 工具目录按需检索：先给模型"工具索引"（名称 + 一行说明，默认 ≤100 条），需要时再注入完整 schema；
- 检索依据：任务类型、当前项目、最近使用、用户偏好；
- 每个工具可附 1–2 个使用示例（提升参数正确率）；
- 目标：避免 50+ 工具约 72K tokens 的固定目录税（Anthropic 2025-11 数据），把工具定义成本从"每轮固定"变成"按需一次"。

## 6. MCP 接入

- 按 MCP 2026-07-28 无状态规范：每请求携带版本与能力，不依赖 initialize 握手/协议级 session；
- 第三方 server 默认 `untrusted`：输出可读不可信，不直接触发高危工具；
- 列表结果可缓存，减少往返；
- 每个 server 独立授权与配额；失败隔离，不拖垮主循环；
- 工具名冲突时加命名空间前缀，避免覆盖内置工具。

## 7. 代码执行（PTC）

- 把"多步工具调用 + 中间数据处理"下沉到沙箱代码里执行，只把最终结论回传；
- 适用：批量文件处理、数据清洗、多源聚合、循环调用工具；
- 约束：沙箱内无凭证、网络默认拒绝、超时与内存上限、产出必须落文件或返回结构化结果；
- 好处：token 与往返次数显著下降（Anthropic 报告复杂研究任务 token −37%），且中间结果天然可回溯。

## 8. 失败处理

| 情况 | 处理 |
|---|---|
| 参数错误 | 返回字段级错误，模型可重试一次 |
| 权限拒绝 | 返回明确原因 + 替代方案（申请审批/换工具） |
| 超时 | 取消并返回部分结果句柄；非幂等不重试 |
| 工具内部错误 | 分类（临时/永久）；临时按退避重试，永久上报 |
| 结果过大 | 溢出落盘 + 摘要 |
| 连续失败 | 同一步骤失败 2 次即升级（换工具/换方案/问人） |

## 10. 指标

| 指标 | 目标（草案） |
|---|---|
| 工具调用成功率 | ≥ 95%（排除模型参数错误后的真实失败） |
| 越权拦截率 | 100%（红队用例） |
| 审批延迟 | P95 ≤ 5 分钟（人可响应时） |
| 工具目录 token 占比 | ≤ 5% |
| 平均每任务工具调用数 | 按任务类型基线，异常升高即告警 |
