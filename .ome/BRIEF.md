# BRIEF — SuperAgent 立项书（P0 草案 · 待用户确认）

> 状态：草案 v0.1 · 2026-11-05 · 结论先行，未签字项标「待确认」
> 本文件只回答四件事：为什么做、为谁做、怎么算成功、什么时候该停。

## 1. 一句话立项
做一个「给目标 → 自主规划 → 调工具执行 → 交付成品」的超级智能体（super agent），先服务单一个人开发者/小团队的可复用工作流，不做通用聊天机器人，也不做企业级 Agent 平台。

## 2. 问题与机会（有出处）
- 2026 被多方称为「智能体爆发年」：基础模型推理/工具调用达标、MCP/A2A 等协议标准化、推理成本两年降幅显著。出处：新华《环球》2026-04-02 圆桌（受访者观点，非统计口径）。
- 工程侧共识仍是「先简单后复杂」：Anthropic《Building effective agents》（2024-12-19）明确指出，成功的实现多数不靠复杂框架，而是简单可组合的模式；workflow 与 agent 要分开设计。2026-05 官方在该文顶部加注：工具格局已变化，现行做法见 Claude Managed Agents。
- 现有产品（Manus、ChatGPT agent/Deep Research、Claude Code、Genspark 等）已覆盖「通用任务交付」，但个人开发者的**可定制、可审计、可复用**工作流仍有空隙（推断，需 P0 内用 3 个用户访谈验证）。

## 3. 目标与非目标
目标（v0.1，任选其一，**待确认**）：
- A. 通用个人任务智能体（研究/整理/写代码/出文档），Web 界面，本地优先；
- B. 单垂直场景的深度智能体（例：代码库维护、资料研究），指标可量化；
- C. Agent 基础设施/框架（给别人搭 agent 用）。

建议：先按 B 收窄到一个场景跑通闭环，再抽象成 A（依据：F-03 简单可组合；F-07 MAST 失败率 41%–86.7%；F-10 多智能体≈15× token；调研综合见 `.ome/research/00-synthesis.md` D1）。

非目标（v0.1 明确不做）：
- 不做通用聊天/陪伴；不做多租户 SaaS；不做自研基础模型；不做移动端；不做插件市场。

## 4. 成功指标（先定度量，阈值待 P1 基线后锁定）
| 指标 | 定义 | v0.1 目标（假设值，待确认） |
|---|---|---|
| 任务完成率 | held-out 20 条任务中，交付物通过验收的比例 | ≥ 60% |
| 人工接管率 | 需人介入才能继续的任务占比 | ≤ 20% |
| 单任务成本 | API + 沙箱费用 | ≤ ¥2 |
| P95 时延 | 从下达到交付 | ≤ 10 分钟 |
| 可复现率 | 同一任务重跑结果可用比例（pass^k 思路） | ≥ 50% |

判定方式：可执行脚本 + 人工验收双轨；可靠性用 pass^3（同任务 3 次全对），不报 pass@1 单次最好成绩；按任务时长分档看成功率。（评测口径详见 `.ome/research/03-eval-market.md`）。

## 5. Kill criteria（触发即停，不硬撑）
| 信号 | 判据 | 动作 |
|---|---|---|
| 场景不收敛 | 2 周内仍无法在 A/B/C 中定一个主场景 | 暂停开发，只做用户访谈 |
| 能力不达标 | 20 条 held-out 任务完成率 < 30% | 放弃通用定位，转单场景 |
| 成本失控 | 单任务平均成本 > ¥5 且两周内无法下降 50% | 重估商业模型或降级模型档 |
| 必须自研模型 | 关键能力只能靠微调/自训解决 | 退出，改用现成模型 + 窄场景 |
| 安全不可控 | 红队用例拦截率 < 80% | 不对外发布 |

## 6. 已知阻塞（≤2）
1. 你要做的「超级智能体」是 A/B/C 哪一种？主场景是什么？（不回答则按 B＝个人开发者的「研究 + 代码/文档交付」推进，标假设）
2. 首版交付形态：本地 Web 应用 / CLI / 桌面端？（默认 Web + CLI 内核，标假设）
