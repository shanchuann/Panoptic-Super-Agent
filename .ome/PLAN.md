# Panoptic Super 开发任务计划

当前阶段为本地项目主对话首段。首段使用固定工作区验证直接问答、局部修改、正式计划与中断恢复。落地接口见 [本地项目主对话](contracts/project-conversation.md)。正式 P1 范围以 [发布定义](design/p1-release.md) 为准。

## DSH 基座与首批二开

| 可以复用的现有能力 | Super Agent 要开发的能力 |
|---|---|
| [Workspace Registry](../packages/workspace/workspace/README.md) 管理目录与会话归属 | P-001 新增项目目标、任务验收判据、任务状态与 Run，复用已有工作区标识 |
| [存储域](../packages/storage/storage-domain/README.md) 与 [Session JSONL](../packages/session/session-persistence-jsonl/README.md) | P-001 通过存储域写入自己的项目记录，在项目域保存与 Session 的关系 |
| [进程内任务](../packages/jobs/jobs-local/README.md)、DSH 工具、沙箱与审批 | P-003 将真实工具调用关联到业务 Run，新增副作用账本、检查点和重启后的结果核对 |
| 已有桌面与 Web 外壳 | U-001 在后端接口通过后接入项目和任务视图 |

B-005 验收的是现有 DSH 基座的构建和启动。**本项目第一张后端实现卡是 P-001 首段**。用独立存储域和 Host 项目服务跑通建项、建任务、读取与重启恢复。

## 执行顺序

| 顺序 | 任务 | 依赖 | 交付与完成判据 | 建议写域 |
|---|---|---|---|---|
| 1 | [B-005 固定开工基线](tasks/B-005.md) | 当前仓库 | 独立检出上安装、类型检查、构建、聚焦回归和无密钥 Web 启动通过。记录提交与命令 | 独立检出、基线证据 |
| 2 | [P-001 项目域与状态机](tasks/P-001.md) | B-005、ADR-0003 | 建项目和任务，进程重启后读回。非法迁移、缺验收判据、依赖成环和双活 Run 均被拒绝。原会话可打开 | 项目服务、存储域、最小装配 |
| 3 | [P-003 执行账本与恢复](tasks/P-003.md) | P-001 的 Task 与 Run 接口、ADR-0010、现有审批和沙箱 | 用测试仓库完成一次获准写入。三个故障点可对账，已提交动作只有一次，取消后无孤儿进程 | 项目 Run、工具调用适配、恢复场景 |
| 4 | [U-001 项目与任务视图](tasks/U-001.md) 的首个场景 | P-001、P-003 | 桌面/Web 能从项目打开任务、查看审批和运行状态，再定位产物与验证证据 | Host 投影与客户端 |
| 旁路 | [B-005 的 Linux 聚焦回归](tasks/B-005.md#instabox-选做检查) | 基线提交已选定 | Instabox 单 worker 测试通过，留存资源记录与测试输出 | 独立测试目录、基线证据 |
| 云端试验 | [CL-001 腾讯云队列持久化](tasks/CL-001.md) | P-001 首段通过 | 独立测试服务通过提交、重启和查询，同一请求只产生一条任务。独立副本恢复通过 | 云端队列存储与 API、测试部署 |
| 云端接入 | [CL-002 接入 Windows 执行器](tasks/CL-002.md) | CL-001、P-003 写入恢复验收 | 单设备完成离线排队、领取、续租、回传、取消。每个 Run 只有当前尝试能提交状态，失联写操作可核对 | 云端调度、Windows 执行适配、客户端状态 |

本地首轮以 B-005、P-001、P-003 和 U-001 的单任务场景为主。B-005 现在可做。P-001 先交付最小持久化验证，再推进状态机和完整卡片。CL-001 可以在 P-001 首段通过后试验，并在 P-003 完成前用合成数据验证云端持久化。CL-002 中能改文件的任务等待本地恢复验收。

任一时刻只推进一个共享源码写入任务。Windows 基线测试、Instabox 聚焦测试和腾讯云运行环境检查可各用独立目录。先检查各自机器的资源与现有服务，再安排实际测试窗口。服务器选择与恢复语义见 [部署方案](design/cloud-local-deployment.md)。

## 从首个场景到 P1 发布

| 任务 | 开工条件 | 验收范围 |
|---|---|---|
| P-002 自然语言建项 | P-001 | 目标、约束、至少一条验收判据和计划确认，缺信息进入澄清 |
| [G-001 模型网关](tasks/G-001.md)、G-002 能力授权 | 基线通过。能力授权与 P-003 的首次写入一起验收 | 首个代码场景使用一个已可用的 BYOK 模型路径。P1 收口再验证模型切换、降级、计量、项目授权与审批 |
| [M-001 最小项目记忆](tasks/M-001.md) | P-001 的项目隔离接口 | 完成 L0/L2 的写、读、删和关闭。清空后检索无命中，跨项目读取被拒绝 |
| [C-001 协调策略](tasks/C-001.md)、[Z-001 任务范式](tasks/Z-001.md) | P-001、P-003；Z-001 同时复用 G-001 的路由 | P1 从单 agent 和单次交接验证 research 与 code。按现有卡片扩展策略和评测 |
| [Y-001 生命周期](tasks/Y-001.md)、[X-001 升级演练](tasks/X-001.md)、O-001 可观测性 | 项目状态、产物和恢复路径稳定 | 完成问询、交付、导入导出、删除及迁移演练。按项目关联运行证据，日志只记录必要字段 |
| REL-001 P1 发布验收 | 上述 P1 需求和图谱场景完成，维护者确认发布范围 | 按发布定义检查七界面六态、数据往返、回滚与交付物，使用已有 DSH 入口做无密钥回归和实际演示 |

后续候选包括 U-002 增量图谱、[U-003 黑板](tasks/U-003.md)、M-002 权重与复习、M-003 记忆整合、M-004 评测、[W-001 事件触发](tasks/W-001.md)、[S-001 旁路智能体](tasks/S-001.md)和 R-006 移动端远程控制。U-003 等待 U-001 和 C-001。M-003 等待 M-002，M-004 等待 M-003 与项目隔离。W-001 和 S-001 从已有项目域及各自 ADR 开始细化。桌面/Web 的首个场景以本地执行为准。完整跨设备数据同步、多执行器和高可用进入 P2 评估。
