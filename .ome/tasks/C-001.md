# C-001 协调策略层 MVP（规则版：最小充分范式 + 按证据升级）

- **编号**：C-001
- **标题**：按任务规模选择协作模式（solo / orchestrator / blackboard）
- **目标**：在项目域与调度器之间加一层规则化的协调策略，输出可解释的协作决策；默认最小充分范式，按证据升级；不引入 LLM 判断。
- **输入**：[ADR-0006](../../docs/adr/ADR-0006-collaboration-model.md)（D1–D10）、[evolution.md](../../.ome/design/evolution.md)、[projects.md §4.4](../../.ome/design/projects.md)、[context.md §2.2](../../.ome/design/context.md)
- **完成判据（可执行 / 可复核）**：
  1. 20 条标注任务样本：路由结果与人工标注一致 ≥75%；
  2. 误升级率（小任务被并行化）≤10%；
  3. 规则版决策耗时 <10ms（本地基准），且不发起模型调用；
  4. 决策写入项目域审计，含 signals、scores、mode、rationale、decidedBy；U-001 的节点详情可查看；
  5. 人工覆盖：项目级可强制模式，生效并写审计；
  6. 升级触发各有单测：上下文占用 >70%、同一步失败 2 次、独立子任务 ≥3；
  7. 迟滞：5 步内不重复切换（单测）；
  8. 调度器只接受 `CoordinationDecision` 对象，不解析自然语言（断言测试）；
  9. 决策对象为三元组（并行度 / 隔离级别 / 人工闸门）+ mode 标签，含 rationale 与触发指标引用；
  10. 启用 M2 前检查 pass^k A/B 记录（D9 门槛），无记录则保持 M0/M1（单测）；
  11. 决策可回链 runId 与 trace（D7），审计可查。
- **验证器**：强（单测 + 样本路由表 + 基准）
- **写域**：`packages/<group>/coordination/**`（新包）、project 域读取接口、`packages/api/*`（决策展示）、`.ome/evidence/C-001/`
- **依赖**：P-001（项目域与状态机）、ADR-0006 Accepted
- **不做**：LLM 边界判断（P2，暂不建卡）、黑板领取/租约（P1.5）、pipeline/hierarchy/debate（P2）、自动并行调度器
- **资源**：L1（开发任务）
- **模型档**：不适用（本任务不调用模型）
- **验收人**：Lead
- **证据目录**：`.ome/evidence/C-001/`（路由表、基准输出、审计样例、单测输出）

## 实现要点

- 规则输入只读项目域与任务元数据，不拉会话历史；
- 决策对象：`{ mode, contextStrategy, parallelism, rationale, escalationTriggers, decidedBy }`；
- 决策缓存与失效：任务状态变化、里程碑、阻塞事件时重算；
- 与 U-001 的接口：节点详情展示 mode 与 rationale；与 P-001 的接口：`ready` 前读取决策。
