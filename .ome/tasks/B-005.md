# B-005 固定 Super Agent 开工基线

目标是在独立检出上证明当前 Panoptic Super 的 DSH 基座可安装、可编译、可启动。依赖为当前仓库的可选提交。计划验收为强验证，桌面与 Web 首页结合人工确认。

## Windows 主检查

1. 选定开工提交并记录完整 SHA。当前分支的聊天状态改动仍在工作区。需要带入时单独记录其差异与归属，正式基线检出使用明确提交。
2. 在新 worktree 和独立 `DSH_HOME` 下依次执行 `pnpm install --frozen-lockfile`、`pnpm run typecheck` 和 `pnpm run build`。每条命令记录退出码与耗时。
3. 运行以下无密钥回归，确认 Session 恢复、文件租约、SDK 事件和现有客户端装配。

```powershell
pnpm exec vitest run packages/session/session-persistence-jsonl/tests/lease.spec.ts packages/session/session-persistence-jsonl/tests/jsonl.spec.ts packages/sdk/server/tests/server.spec.ts --maxWorkers 2
pnpm run test:web:built apps/web/tests/built-boot.expected.e2e.ts
pnpm dsh web --patch apps/web/tests/pin-browse-picker.overlay.yml --port 0 --no-open
```

确认实际浏览器加载可用，页面和左上角显示 Panoptic 品牌。测试统计分开记录通过、失败与跳过。日志中移除启动令牌及密钥。交付为选定 SHA、命令、结果与截图，记录在 `.ome/evidence/B-005/`。主工作区的未提交改动由原任务继续管理。

## Instabox 选做检查

保持原有服务运行。使用 `free -h` 与 `df -h / /data /tmp` 确认余量，选低负载窗口，用独立目录检出同一提交。先以 `--maxWorkers 1` 执行 Session 租约和 JSONL 测试，余量稳定后用 `DSH_GATE_CONCURRENCY=1 pnpm run typecheck`。资源记录包含测试前后及峰值、剩余时限和现有服务健康状态。出现持续换页、服务退化或磁盘余量不足时，结束测试进程，Windows 基线验证独立推进。

写域为独立检出的构建产物、临时 Harness home、B-005 证据与状态记录。验收人核对证据来自同一提交。
