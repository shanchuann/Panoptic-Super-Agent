# CL-002 云队列接入 Windows 执行器

开工条件为 [CL-001](CL-001.md) 的云端持久化验收和 [P-003](P-003.md) 的本地写入恢复验收。首版只登记一个 Windows 执行器，先使用只读任务联调。等领取互斥、断网恢复和取消通过，再用隔离项目验证一次经审批的写入。

| 子任务 | 交付 | 必测行为 |
|---|---|---|
| CL-002a 领取与续租 | 设备凭证、项目绑定、原子领取、尝试号和租约 | 离线可排队，上线可领取。并发领取只有一个获得当前执行权。失效尝试的状态不能覆盖当前任务 |
| CL-002b 事件回传 | 本机持久保存待发事件，云端按 Run、尝试号、序号去重，确认连续落盘位置 | 断网再连按游标续传。重复和乱序事件不产生错误终态。重启云服务后可继续查询 |
| CL-002c 失联、取消与对账 | 连接 DSH 的取消和清理。失联后停止启动新步骤，待核对写入保持锁定，确定原尝试已释放后才可改派 | 取消后无遗留进程。断开时已有副作用只发生一次。旧执行器恢复后不能继续启动过期任务 |

接口与状态沿用 [部署方案](../design/cloud-local-deployment.md#调度断线和恢复)。真实任务只通过本机登记的工作区标识与现有批准路径运行。凭证按设备撤销。完整 Session 与模型密钥留在本机。

验收使用本机断网夹具和独立腾讯云测试服务。用同一条任务记录展示提交、领取、暂停、续传、完成或待核对。证据保存请求标识、尝试号、游标与写入计数。Instabox 仅在这条链路稳定后用于短时任务的暂停和停机演练。

写域为调度领取、事件接收、Windows 执行适配、客户端状态提示、测试和 `.ome/evidence/CL-002/`。子任务分别交付与回滚。维护者复核设备授权和写入恢复结果。
