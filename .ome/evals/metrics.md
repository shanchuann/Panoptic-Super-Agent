# 评测口径：五项指标与 pass^k（v0.3）

> 配套：`.ome/evals/tasks.jsonl`（20 条 held-out，另扩到 30 条）、SPEC §3 NFR、BRIEF §4、ADR-0001 D6
> 2026-11-07 更新：**不记预算、不计量费用**；只保留时长/步数/重试等资源上限。目标值按任务时长分档、基线后锁定。

## 0. 锁定策略

- **已锁**：指标定义、任务集、判定人、资源上限（时长/步数/重试）；
- **待锁**：目标值，先跑 20 条 × 3 次得到 baseline，发布门槛 = max(下表下限, baseline + 10pp)；
- 若 baseline < 30%，触发 BRIEF §5 kill criteria（转单场景或停）。

## 1. 资源上限（已锁，不计费用）

| 约束 | 值 | 动作 |
|---|---|---|
| 单次运行时长 | ≤30 分钟 | 暂停并给出续跑点 |
| 单任务步数 | ≤120 步 | 中止并保留中间产物 |
| 单步重试 | ≤2 次 | 升级模型或转人工 |

## 2. 分档目标（目标值待基线后锁定）

| 任务档 | 完成率 | 人工接管率 | P95 时长 | 稳定性 |
|---|---|---|---|---|
| 快任务（<15 分钟） | ≥70% | ≤15% | ≤10 分钟 | pass^3 ≥50%（当前 20 条以 15–60m/>60m 为主，<15m 档在扩展集补充） |
| 中任务（15–60 分钟） | ≥50% | ≤25% | ≤60 分钟 | pass^2 |
| 长任务（>60 分钟） | 不承诺（目标 ≥25%） | ≤40% | 不报 P95，报可暂停/恢复 | pass^1 + 人工验收 |

## 3. 指标定义

| 指标 | 定义 | 计算 |
|---|---|---|
| 任务成功率 | 交付物通过判据的任务占比 | passed / total |
| pass^k | 同一任务连续 k 次全部通过的比例（可靠性，不是最好成绩） | k 次全过任务数 / total |
| 人工接管率 | 需人介入（审批之外）才能继续的任务占比 | taken_over / total |
| P95 完成时长 | 从 run 到 artifact 完成，按任务档统计 | p95(durationMs) per band |
| 用量（诊断） | token、步数、重试次数 | 只记录不换算金额 |

## 4. 报告格式（report.json）

```json
{ "runId": "...", "set": "tasks.jsonl", "k": 3, "startedAt": "...",
  "summary": { "successRate": 0.0, "passK": 0.0, "humanTakeoverRate": 0.0 },
  "byDurationBand": { "<15m": {}, "15-60m": {}, ">60m": {} },
  "tasks": [ { "id": "TASK-001", "band": "<15m",
               "runs": [ { "ok": true, "steps": 24, "durationMs": 120000 } ] } ],
  "failures": [ { "id": "TASK-014", "reason": "缺来源链接", "evidence": "..." } ] }
```

## 5. 判分规则

- 判据以 tasks.jsonl 的 `criteria` 为准，逐条二元判定；缺一条即失败；
- 能用脚本判的优先脚本（verifier=script / script+human），人工只判风格与完整性；
- 同一任务 k 次跑完才算 pass^k；中途人工接管按失败计，单列接管率；
- 失败必须归因到类别：规划 / 工具 / 上下文 / 验证 / 超时 / 步数 / 安全；
- 报告必须按档位拆分，不允许只报全局平均。

## 6. 反作弊

- 任务集不得在 prompt 里泄露实现细节或期望输出；
- 每次评测前重跑基线（防止模型/工具变化漂移）；
- 20 条中保留 ≥6 条作为最终验证集，不参与调参与基线迭代；
- 失败任务计入分母，不允许剔除；
- pass^k 防止只报"最好一次"。

## 7. 记忆专项指标（M-004 产出）

| 指标 | 目标（草案） |
|---|---|
| 抽取准确率 / 重复率 | ≥90% / ≤5% |
| Recall@8 / 陈旧事实注入率 | ≥80% / ≤5% |
| 记忆注入 token 占比 | ≤15% |
| 删除彻底性（删除后命中数） | 0 |
| 有/无记忆的 pass^k 差 | ≥+10pp |

## 8. 拓扑升级门槛（D9）

- 任何 M2 及以上协作拓扑进入默认路径前，必须有自家 pass^k A/B 对照（同任务集、同预算、≥3 次）；
- 对照记录：任务集版本、模型、模式、pass^k、用量、人工接管率；无显著提升则保持 M0/M1；
- 实验记录写项目域审计，可复查。

## 9. 记忆评测（M-004）

- 主用 MemoryAgentBench（ICLR 2026，AR/TTL/LRU/CR 四能力）与 MemoryArena（ICML 2026，agentic 任务）；
- LongMemEval 作能力分项参照；LoCoMo 仅作回归防倒退（已近饱和）；
- 任何机制提升必须附消融；报告"记忆是否指导了下一步动作"的成功率。
